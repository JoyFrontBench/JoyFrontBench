一级分类：数据可视化
二级分类：

请从 0 到 1 实现一个基于 React 生态的前端项目，工具名称为：

**流量曲线编辑工具**

该工具用于导入本地 CSV 数据，对不同日期、不同用户分层下的流量曲线进行可视化展示、拖拽编辑、批量编辑、联动编辑，并支持按日期导出编辑后的 JSON 数据。

请不要假设已有项目或已有组件存在，需要完整创建一个可运行的 React 前端项目，包括项目结构、依赖配置、核心组件、样式和启动说明。最终交付物应为一个完整 React 工程项目，而不是单文件 HTML。

---

## 1. 总体实现方式

第一版只实现纯前端本地工具，不接入后端接口。

整体流程为：

```text
本地上传 CSV → 前端解析 → 前端标准化数据 → 前端展示曲线 → 前端编辑曲线 → 前端导出 JSON
```

不需要实现以下后端能力：

1. 不需要服务端上传接口；
2. 不需要数据库；
3. 不需要登录鉴权；
4. 不需要保存历史版本；
5. 不需要多人协作；
6. 不需要服务端导出接口。

所有数据处理、编辑和导出均在浏览器本地完成。

## 2. 技术要求

1. 使用 React 生态实现，建议使用 Vite + React + TypeScript。
2. 请交付完整 React 项目工程，包括 `package.json`、`index.html`、`src` 目录、组件文件、工具函数文件、样式文件等。
3. 项目应能通过以下方式本地运行：

```bash
npm install
npm run dev
```

4. 可自行选择图表实现方案，例如 ECharts、Recharts、D3、SVG 或 Canvas，但必须支持曲线数据点拖拽编辑。
5. 不要求使用贝塞尔曲线。曲线编辑应以“时间序列数据点编辑 + 邻域平滑影响”的方式实现。
6. 不允许出现引用未定义组件的问题，例如使用了某个组件但未定义或未导入。

8. 所有图表、筛选、编辑、导出逻辑必须基于同一套标准化后的数据源。

## 3. 输入数据格式

工具支持导入本地 CSV 文件。

CSV 字段固定为：

| 字段名           | 含义          | 是否必须 |
| ------------- | ----------- | ---- |
| `channel_id`  | 渠道 ID       | 是    |
| `strategy_id` | 策略 ID       | 是    |
| `dt`          | 日期          | 是    |
| `time`        | 时间点         | 是    |
| `count`       | 流量数值        | 是    |
| `user_layer`  | 用户分层 / 人群分层 | 是    |

示例：

```csv
channel_id,strategy_id,dt,time,count,user_layer
CH001,ST001,2026-07-01,00:00,12.50,L01_人群分层01
CH001,ST001,2026-07-01,00:10,13.20,L01_人群分层01
CH001,ST001,2026-07-01,00:20,14.00,L01_人群分层01
CH001,ST001,2026-07-01,00:00,8.10,L02_人群分层02
```

不得依赖评测者另行提供输入文件。交付物必须自行生成并包含一份确定性的 `tests/fixtures/traffic.csv`（或等价仓库内路径），覆盖题面所需渠道、策略、日期、12 个人群及指定缺失点；自动化测试直接上传该 CSV，评测不要求 XLSX。

## 4. 时间粒度规则

时间粒度固定为 **10 分钟**。

每天标准时间点数量为：

```text
24 小时 × 每小时 6 个时间点 = 144 个时间点
```

时间格式固定为：

```text
HH:mm
```

例如：

```text
00:00
00:10
00:20
...
23:50
```

要求：

1. 每条曲线最终都必须补齐为 144 个点。
2. 时间轴必须统一为从 `00:00` 到 `23:50` 的 144 个时间点。
3. 如果 CSV 中某个日期、某个人群缺少某些时间点，也必须在图上展示这些时间点。
4. 缺失时间点的 `count` 按 `0` 处理。
5. 所有曲线都必须基于相同的 144 个时间索引，避免拖拽、联动、导出时索引错位。
6. `count` 需要解析为数值类型，异常值、空值或无法解析的值按 `0` 处理。
7. 拖拽、批量编辑和导出时均以这 144 个标准时间点为准。

## 5. 用户分层规则

CSV 中的 `user_layer` 表示用户分层。

测试数据中可能包含 12 个用户分层，例如：

```text
L01_人群分层01
L02_人群分层02
L03_人群分层03
L04_人群分层04
L05_人群分层05
L06_人群分层06
L07_人群分层07
L08_人群分层08
L09_人群分层09
L10_人群分层10
L11_人群分层11
L12_人群分层12
```

要求：

1. 用户分层选项应根据 CSV 中的 `user_layer` 自动生成。
2. 不要写死用户分层名称。
3. 当某个日期下存在 12 个人群时，按 4 行 × 3 列展示。
4. 如果实际人群数量不是 12 个，则按照每行 3 列的网格自适应展示。
5. 每个日期内的人群曲线按照当日总流量从大到小排序。

## 7. 筛选功能

### 7.1 渠道 ID 筛选

1. 渠道 ID 筛选框根据 CSV 中的 `channel_id` 自动生成选项。
2. 渠道 ID 不需要“全部”选项。
3. 默认选择第一个可用渠道 ID。
4. 用户切换渠道 ID 后，页面只展示该渠道 ID 下的数据。

### 7.2 策略 ID 筛选

1. 策略 ID 筛选框根据当前数据中的 `strategy_id` 自动生成选项。
2. 策略 ID 不需要“全部”选项。
3. 默认选择第一个可用策略 ID。
4. 用户切换策略 ID 后，页面只展示该策略 ID 下的数据。

### 7.3 用户分层筛选

1. 用户分层筛选框根据 CSV 中的 `user_layer` 自动生成选项。
2. 用户分层筛选框必须包含“全部”选项。
3. 默认选择“全部”。
4. 选择“全部”时，展示当前渠道 ID 和策略 ID 下的所有用户分层曲线。
5. 选择某个具体用户分层时，只展示该用户分层对应的曲线。
6. 用户分层筛选必须真实影响图表展示、批量编辑范围和联动编辑范围，不能只改变下拉框状态。

## 8. 曲线展示方式

页面按日期纵向展示数据。

每个日期为一个独立区域。每个日期区域内展示该日期下不同用户分层的曲线卡片。

当用户分层选择“全部”时，每个日期展示该日期下所有用户分层曲线。通常有 12 个人群分层，应采用 **4 行 × 3 列** 的布局展示。若实际人群数量不是 12 个，则保持每行 3 列的自适应网格布局。

每个日期下的人群曲线需要按照该人群当日总流量从大到小排序。

每个曲线卡片中需要展示：

1. 当前日期；
2. 当前用户分层名称；
3. 当日总流量；
4. 当前展示的曲线类型；
5. 曲线切换按钮；
6. 曲线图；
7. 当前曲线编辑状态提示。

## 9. 流量曲线与累计占比曲线

每个人群曲线卡片中需要支持两种曲线：

1. 流量曲线；
2. 累计占比曲线。

两种曲线放在同一个卡片中，不要左右并排展示。通过一个“切换曲线”或“翻转”按钮在两种曲线之间切换。

默认展示流量曲线。

---

### 9.1 流量曲线

1. 横坐标为时间，粒度为 10 分钟。
2. 纵坐标为流量值 `count`。
3. 每条曲线包含 144 个点。
4. 支持拖拽编辑数据点。
5. 当拖拽点接近或超过当前纵坐标上限时，纵坐标上限应自动扩展，不能限制用户继续向上拖拽。
6. 流量值不允许为负数，最小值为 0。
7. 流量值允许小数。
8. 页面展示和导出时，流量值保留两位小数。

---

### 9.2 累计占比曲线

累计占比曲线由流量曲线计算得到。

计算逻辑为：

```text
cumulative_ratio[i] = sum(flow_values[0..i]) / sum(flow_values[0..143])
```

要求：

1. 累计占比曲线横坐标为时间，粒度为 10 分钟。
2. 纵坐标为当日累计流量占比。
3. 最后一个点应为 1 或接近 1。
4. 如果当日总流量为 0，则累计占比数组全部为 0。
5. 当流量曲线发生变化时，累计占比曲线必须立即重新计算并更新展示。
6. 页面展示和导出时，累计占比保留两位小数。

---

### 9.3 双向联动

需要支持流量曲线与累计占比曲线之间的数据联动：

1. 编辑流量曲线时，自动重新计算累计占比曲线。
2. 编辑累计占比曲线时，需要反向更新流量曲线。
3. 编辑累计占比曲线时，应保证累计占比非负、单调不下降，最终值归一化到 1。
4. 从累计占比曲线反推流量曲线时，保持当前曲线总流量不变，通过相邻累计占比差值计算各时间点流量：

```text
flow_values[i] = (cumulative_ratio[i] - cumulative_ratio[i-1]) * total_flow
```

其中 `cumulative_ratio[-1]` 视为 0。

## 10. 曲线拖拽编辑

工具必须支持直接在图表上拖拽数据点进行编辑。

拖拽编辑需要满足：

1. 拖拽时能够实时更新当前曲线数据；
2. 拖拽结束后保存到全局数据状态中；
3. 图表必须立即重新渲染；
4. 当前曲线对应的另一种曲线必须同步更新；
5. 拖拽后的数据不能为负数；
6. 拖拽超过纵轴上限时，纵轴应自动拉高；
7. 编辑结果必须影响后续导出数据；
8. 不能只改变图表局部显示，必须真实修改标准化后的数据源。

## 11. 编辑模式

工具需要支持两组编辑模式，且两组模式可以组合使用。

第一组是影响范围模式：

1. 单曲线编辑模式；
2. 同日人群联动编辑模式。

第二组是编辑精度模式：

1. 精准模式；
2. 模糊模式。

编辑模式选择区域放在批量编辑工具下方。

---

### 11.1 单曲线编辑模式

单曲线编辑模式下，用户拖拽某个日期、某个人群、某个时间点时，只影响当前这条曲线。

例如拖拽：

```text
日期 = 2026-07-01
人群 = L01_人群分层01
时间 = 10:20
```

则只修改该日期、该人群、该时间点或其模糊影响范围内的数据，不影响其他日期、其他人群。

---

### 11.2 同日人群联动编辑模式

同日人群联动编辑模式下，用户拖拽某个日期、某个人群的曲线时，同一日期下当前筛选条件范围内的其他人群曲线也要同步变化。

联动逻辑优先采用等比例缩放。

例如当前拖拽点从 100 调整为 150，则缩放比例为：

```text
150 / 100 = 1.5
```

同一天、当前筛选条件下的其他人群在相同时间点也应乘以 1.5。

如果当前拖拽点原始值大于 0，则使用比例缩放：

```text
ratio = newValue / oldValue
```

如果当前拖拽点原始值等于 0，则使用差值调整：

```text
delta = newValue - oldValue
```

并将该差值应用到同一天、当前筛选条件下的其他展示人群的相同时间点。

联动范围必须明确：

1. 只影响当前渠道 ID；
2. 只影响当前策略 ID；
3. 只影响当前日期；
4. 只影响当前用户分层筛选条件下正在展示的人群；
5. 如果用户分层选择“全部”，则影响当前日期下所有展示的人群；
6. 如果用户分层选择某一个具体人群，则只影响该人群；
7. 不得修改未被当前筛选条件覆盖、未展示的数据。

联动编辑后，所有受影响人群的流量曲线和累计占比曲线都必须重新计算并立即重新渲染。

---

### 11.3 精准模式

精准模式下，拖拽一个点只编辑该点。

例如拖拽 `10:20`，只修改 `10:20` 这个 10 分钟时间点。

---

### 11.4 模糊模式

模糊模式下，拖拽一个点时，需要同时影响该点周围的一片时间点，避免用户必须逐个拖拽 144 个点。

模糊模式默认影响半径为：

```text
±3 个点
```

由于时间粒度为 10 分钟，因此默认影响当前点前后 30 分钟范围，总共最多影响 7 个点。

例如拖拽 `10:20`，默认影响：

```text
09:50
10:00
10:10
10:20
10:30
10:40
10:50
```

模糊模式需要支持用户选择影响半径：

1. ±1 个点；
2. ±2 个点；
3. ±3 个点；
4. ±6 个点。

默认值为 ±3 个点。

模糊模式采用线性衰减权重，距离中心点越近影响越大，越远影响越小。

当半径为 ±3 时，权重为：

```text
中心点权重 = 1.00
距离 1 个点 = 0.75
距离 2 个点 = 0.50
距离 3 个点 = 0.25
```

要求：

1. 拖拽一个点时，必须真实更新多个时间点，而不是只更新当前点。
2. 更新后需要给出清晰提示，例如“模糊模式已更新当前曲线 7 个时间点”。
3. 如果同时处于同日人群联动编辑模式，则应更新当前日期、当前筛选条件下多个用户分层的多个时间点。
4. 提示中的“更新了多少人群、多少时间点”必须与真实数据更新范围一致。
5. 所有被模糊模式影响的点都必须在图形上立即体现变化。

## 12. 批量编辑工具

批量编辑工具用于快速修改某些日期、某些人群、某个时间段内的数据。

批量编辑工具需要支持：

1. 日期选择；
2. 用户分层选择；
3. 开始时间选择；
4. 结束时间选择；
5. 编辑操作选择；
6. 参数输入；
7. 应用按钮；
8. 操作结果提示。

时间段选择必须精确到 10 分钟，不能只按小时编辑。

例如支持选择：

```text
10:00 - 10:30
20:10 - 22:40
00:00 - 07:50
```

批量编辑操作至少支持：

1. 将选中时间段流量置为 0；
2. 将选中时间段流量乘以某个倍数；
3. 将选中时间段流量增加或减少某个固定值；
4. 将选中时间段流量设置为某个固定值。

批量编辑后：

1. 对应流量曲线必须更新；
2. 对应累计占比曲线必须重新计算；
3. 图表必须立即重新渲染；
4. 后续导出的 JSON 必须使用编辑后的数据。

## 14. 导出功能

导出功能按日期维度实现。

每个日期区域提供一个导出按钮。

每次导出当前日期下、当前筛选条件范围内所有展示人群的曲线数据。

导出建议采用一个 JSON 文件，同时包含 `flow_values` 和 `cumulative_ratio`，避免两个文件之间丢失对应关系。

导出 JSON 结构如下：

```json
{
  "metadata": {
    "channel_id": "CH001",
    "strategy_id": "ST001",
    "dt": "2026-07-01",
    "time_granularity": "10min",
    "points_per_day": 144
  },
  "flow_values": {
    "L01_人群分层01": [12.50, 13.20, 14.00],
    "L02_人群分层02": [8.10, 9.30, 10.20]
  },
  "cumulative_ratio": {
    "L01_人群分层01": [0.01, 0.02, 0.03],
    "L02_人群分层02": [0.01, 0.02, 0.04]
  }
}
```

要求：

1. `metadata` 中记录当前导出的渠道 ID、策略 ID、日期、时间粒度和每日点数。
2. `flow_values` 的 key 为用户分层名称，value 为该用户分层在当前日期下 144 个时间点的流量数值列表。
3. `cumulative_ratio` 的 key 为用户分层名称，value 为该用户分层在当前日期下 144 个时间点的累计占比列表。
4. 每个 value 数组长度必须为 144。
5. 流量值保留两位小数。
6. 累计占比值保留两位小数。
7. 导出数据必须基于用户编辑后的最新状态。
8. 导出文件名中应包含日期、渠道 ID、策略 ID，例如：

```text
traffic_curve_2026-07-01_CH001_ST001.json
```
