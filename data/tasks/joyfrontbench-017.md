一级分类：数据可视化
二级分类：数据看板

请你扮演一名资深数据新闻可视化前端工程师，开发一个完全本地运行的《汐线周刊 · 数据新闻可视化看板生成器》。编辑把 CSV 或 JSON 数据导入工作台后，系统要识别字段类型、推荐图表组合、生成一组可交互的数据新闻看板图表，并允许用户通过筛选、分组、排序、指标切换和联动高亮探索数据，最后导出一份可离线打开的可视化故事页和一份机器可读的看板配置 JSON。

这不是合规审校台、静态图片展示页、普通表格浏览器或只摆 KPI 卡片的后台 Dashboard。成功状态必须由“导入数据 → 字段识别 → 图表生成 → 看板联动 → 洞察标注 → 图像/HTML 导出 → reload 恢复”完整闭环证明。用户的主要任务是把数据变成可阅读、可交互、可导出的数据新闻看板。

交付形式必须是一个可运行的多文件前端工程，而不是单 HTML 文件。禁止请求真实新闻 API、远程文件、外部图片、外部字体、云端数据库、在线 AI 服务或后端接口。所有示例数据、解析、图表、图像导出和看板状态都在浏览器本地完成。`package.json` 不得使用 `latest`。

## 一、工程结构与边界

1. 必须包含 `package.json`、`index.html`、`src/main.tsx`、`src/App.tsx`、`README.md`。
2. `package.json` 至少提供 `npm run dev`、`npm run build`、`npm run test`、`npm run typecheck` 或 `npm run lint`；若提供 e2e，则 `@playwright/test` 固定版本。
3. 至少定义以下 TypeScript 类型：`ImportedDataset`、`DataColumn`、`DataRow`、`ColumnRole`、`ChartKind`、`ChartSpec`、`DashboardCard`、`DashboardState`、`FilterState`、`SortState`、`InsightAnnotation`、`ExportBundle`、`PersistedDashboard`。
4. 推荐目录：`src/components/importer/`、`src/components/dashboard/`、`src/components/charts/`、`src/domain/data/`、`src/domain/charts/`、`src/domain/dashboard/`、`src/domain/export/`、`src/state/`、`src/utils/`、`src/test/`。
5. CSV/JSON 解析、字段类型推断、缺失值处理、统计聚合、图表推荐、图表几何生成、筛选联动、洞察标注、导出 HTML/PNG/SVG/JSON 和持久化恢复必须拆分为不依赖 React 的可测试模块。
6. 图表可以用项目自绘 SVG/Canvas；不允许直接用 ECharts、Chart.js、D3 等库替代核心图表渲染逻辑。可以用轻量解析库，但不能把图表生成、聚合和联动逻辑外包给不可检查的库。
7. 不使用 `dangerouslySetInnerHTML` 渲染导入数据，不把完整页面或大段组件写成字符串模板，不在渲染或导出路径中使用不可复现随机数。

## 二、界面与主流程

桌面端应呈现“数据新闻编辑台 + 看板画布”的工作方式：

- 顶部：项目标题、当前数据集、导入入口、示例数据入口、全局筛选摘要、导出入口。
- 左侧：数据源与字段面板，展示字段类型、缺失率、唯一值数量、示例值、角色设置和字段映射。
- 中间：数据新闻看板画布，至少包含 4 张图表卡片、1 张关键指标卡和 1 个洞察标注层。
- 右侧：图表配置与洞察面板，可切换图表类型、维度、指标、聚合方式、排序方式、颜色编码、注释和导出设置。
- 底部或抽屉：数据预览表、导入错误、转换日志和当前看板 JSON 预览。

核心闭环必须完整可执行：

```text
选择示例数据或导入 CSV/JSON
→ 字段识别与数据质量提示
→ 自动生成看板图表
→ 调整字段映射和图表类型
→ 使用全局筛选与图表点击联动
→ 添加洞察标注
→ 导出图像/HTML/JSON
→ reload 恢复看板
→ Reset 回到示例数据
```

## 三、固定示例数据与导入能力

1. 内置至少 3 套确定性示例数据，且默认加载其中一套：
   - `city-commute-2026`：城市通勤方式、区域、月份、人数、平均通勤时长、碳排估算，至少 72 行。
   - `climate-risk-2026`：城市、日期、温度、降雨、风险等级、预警类型，至少 90 行。
   - `public-budget-2026`：部门、项目、预算、实际支出、季度、变化率，至少 60 行。
2. 示例数据必须覆盖数值、分类、日期、百分比、地理/区域、枚举等级和文本说明字段。
3. 支持导入本地 CSV 和 JSON：
   - CSV 支持逗号分隔、带表头、双引号转义、空值和数字百分号。
   - JSON 支持对象数组；若根对象包含多个数组，应让用户选择一个数组作为数据表。
   - 非法 CSV/JSON、空数据、字段不一致、嵌套对象无法表格化时，必须显示明确错误并保留当前看板。
   - 不得依赖评测者另行提供数据文件；交付物必须自行生成并包含可供自动化测试上传的确定性 fixtures，至少包括合法 CSV、多数组 JSON 和非法 JSON。
4. 字段类型推断至少区分：`number`、`category`、`date`、`percent`、`region`、`text`、`boolean`。推断结果可人工改写，改写后图表和推荐立即重算。
5. 每个字段展示缺失率、唯一值数量、最小/最大值或前 5 个类别样例。数据质量警告至少包含：空值过多、日期解析失败、数值列混入文本、类别过多、百分比超出 `0..100`。
6. 导入或切换示例数据后，自动生成初始看板：至少 4 张图表卡片 + 1 张 KPI 卡，且每张卡的字段映射来自当前数据集，不得写死只识别示例字段名。

## 四、图表类型与数据可视化规则

必须实现至少 8 种图表/卡片类型，全部由当前数据派生：

1. `metric-card`：关键指标卡，显示总量、平均值、同比/环比或最大值。
2. `bar`：分类对比，支持横向或纵向，基线从 0 开始。
3. `stacked-bar`：分类构成，支持百分比堆叠。
4. `line`：时间序列趋势，支持多系列。
5. `area`：趋势面积图，必须可切换为减弱填充的可读模式。
6. `scatter`：两个数值字段关系，支持颜色按类别编码。
7. `heatmap`：两个分类/日期维度交叉矩阵，颜色表达聚合值。
8. `small-multiples`：按类别拆分的小多图，至少支持 bar 或 line 的小图。
9. 可选：`map-grid` 或 `region-tile`，用本地 SVG 区域格子图表达区域数据，不使用外部地图瓦片。

图表推荐规则：

1. `date + number` 优先推荐 `line` / `area`。
2. `category + number` 优先推荐 `bar`。
3. `category + category + number` 优先推荐 `stacked-bar` / `heatmap`。
4. `number + number` 优先推荐 `scatter`。
5. `region + number` 优先推荐 `region-tile` 或 `bar`。
6. 类别超过 12 时，bar 默认只显示 Top N 并把其余合并为“其他”；页面必须说明合并规则。
7. 百分比字段用于 stacked-bar 时应显示总和校验，超过 100 或小于 100 时给出提示但不阻断渲染。

每张图表必须有：结论式标题、说明字段含义的副标题、图例、单位、来源/数据集名、空状态和图表级配置入口。图表不能只是随机形状或占位插画。

## 五、看板联动、筛选与派生状态

1. 全局筛选至少支持：日期范围、一个分类字段多选、一个数值范围。筛选结果必须为条件交集，所有图表、KPI、数据表和洞察标注从同一份 filtered rows 派生。
2. 点击图表元素可设置交叉筛选或高亮：
   - 点击 bar 类目 → 过滤或高亮该类目；
   - 点击 line 点 → 聚焦对应日期；
   - 点击 scatter 点 → 在数据表中定位对应行；
   - 点击 heatmap 单元 → 应用两个维度的交叉条件。
3. 所有筛选与高亮必须显示为可移除的 filter chip。清除 chip 后看板恢复。
4. 图表之间必须联动：任一图表产生筛选后，其他图表的聚合、KPI 和数据表立即更新；不得只改变当前图表视觉。
5. 支持排序：bar 图按值升/降、按类目名、按原始顺序；排序状态进入看板 JSON 并可恢复。
6. 支持图表配置：改变图表类型、维度字段、指标字段、聚合方式（sum/avg/count/min/max）、颜色字段、Top N 后，图表几何和标题/副标题同步更新。
7. 所有派生结果必须可由 `DashboardState + ImportedDataset` 重算；不能在组件内部复制一套图表数据导致状态不同步。

## 六、洞察标注与数据故事

1. 用户可以给任意图表添加洞察标注，至少包含：标题、说明、绑定图表 id、可选绑定字段/类别/日期、重要性 `low | medium | high`。
2. 标注应显示在对应图表卡片中，可编辑、删除、折叠。删除图表时，相关标注必须级联删除或提示迁移。
3. 系统自动给出至少 3 条候选洞察，例如最大值、最小值、增长最快、异常离群点、Top 类别集中度。候选洞察来自当前 filtered rows，筛选变化后重算。
4. 用户采纳候选洞察后写入看板状态，并在导出 HTML 中随对应图表展示。
5. 洞察文案必须基于真实聚合值生成，不能写死示例结论。

## 七、导出与持久化

1. 支持导出当前看板为：
   - 单 HTML 文件：离线可打开，包含图表、标题、副标题、图例、标注、筛选摘要和来源说明；不得包含编辑器侧栏、字段面板或配置控件。
   - SVG 或 PNG 图像：至少支持导出当前选中图表为 SVG；若实现 PNG，必须说明浏览器兼容边界。
   - 看板 JSON：包含 dataset schema、chart specs、filters、sorts、annotations、theme、source metadata 和生成时间。
2. 同一数据与同一看板状态下连续导出两次，HTML 中的图表 SVG 几何和 JSON 内容必须一致；导出时间字段可单独标记并不得影响图形签名。
3. localStorage 保存当前数据集摘要、字段类型改写、看板配置、筛选、排序、标注、当前选中图表和最近导出提示。
4. reload 后恢复看板；如果导入文件本体无法持久保存，应保存行数据快照或明确提示当前浏览器本地保存范围。
5. 读到损坏 JSON、缺字段图表、悬空字段映射、非法枚举、过大数据快照时不能白屏；应丢弃坏卡片或回退示例数据，显示恢复提示和 Reset 入口。
6. Reset 清除导入数据、筛选、标注和配置，恢复默认示例数据与初始看板。

## 八、视觉风格、响应式与可访问性

1. 视觉方向是“数据新闻编辑室 + 现代可视化看板”：浅色高对比底、清晰网格、纸白卡片、墨蓝标题、珊瑚强调、青绿正向、琥珀提示、克制动效。不要做黑蓝赛博监控台、金融交易皮肤、泛化 SaaS 卡片墙或营销落地页。
2. 图表是主要视觉主体，桌面端看板区域应占据首屏最大面积；字段面板和配置面板作为辅助，不得喧宾夺主。
3. 图表颜色、线型、点形、纹理和文字标签共同表达含义，不能只靠颜色区分系列或状态。
4. 360px 下可以用“数据 / 看板 / 配置 / 导出”底部导航或等价结构；必须能完成导入示例数据、查看图表、筛选、编辑图表配置、添加标注和导出 JSON/HTML。
5. 键盘可完成数据集切换、字段选择、图表卡片聚焦、筛选 chip 删除、图表配置、标注编辑和导出。
6. 所有输入控件有 label，图表有可访问名称和数据摘要；hover、active、focus、disabled 状态清晰。
7. `prefers-reduced-motion` 下关闭非必要入场动画、点线过渡和高亮脉冲，但筛选变化和图表更新仍要有文字状态反馈。

## 九、性能

1. 在 500 行以内数据上进行字段推断、4 张图表重聚合和全局筛选时，不出现明显卡顿或界面闪烁。
