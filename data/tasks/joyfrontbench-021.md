一级分类：应用
二级分类：闯关游戏

请你扮演一名资深游戏前端工程师，擅长儿童教育产品、触控拖拽、反馈循环和可测试游戏状态机。请实现一个儿童垃圾分类街区闯关游戏：玩家在卡通街区中把不断出现的垃圾物品拖到正确垃圾桶，通过即时反馈、连击奖励、错题复盘和徽章解锁学习垃圾分类。

交付形式必须是一个可运行的多文件前端工程，而不是单个 HTML 文件。请使用 Vite + React + TypeScript 实现；Canvas、SVG、Pointer Events、Vitest 和 Playwright 均可通过 npm 依赖引入。禁止请求在线题库、外部图片、远程音效或外部服务；所有物品、关卡、分数、假玩家 leaderboard 必须 deterministic。

工程结构要求：

1. 必须包含 package.json、index.html、src/main.tsx、src/App.tsx、README.md。
2. package.json 至少提供 npm run dev、npm run build、npm run test、npm run lint 或 npm run typecheck。
3. 至少拆分出以下职责模块：
   - 关卡、垃圾物品、垃圾桶和徽章数据
   - 分类判定、计分、连击和关卡完成 reducer
   - 拖拽命中检测和 pointer 坐标转换
   - 错题复盘、学习卡片和 replay 关卡派生逻辑
   - 本地 leaderboard seed、排序和同分规则
   - 进度持久化、reset 和坏值回退工具
   - 街区场景、垃圾物品、垃圾桶、反馈动画、结算面板、关卡地图、徽章墙和 leaderboard 组件
5. 至少定义 WasteItem、WasteCategory、Bin、LevelConfig、GameSession、ComboState、MistakeRecord、RewardBadge、LeaderboardEntry 等 TypeScript 类型。
6. 分类判定、关卡生成、计分、连击、错误复盘、徽章解锁和 leaderboard 排序必须放在可测试的纯函数或 reducer 中。
7. 不允许使用 dangerouslySetInnerHTML，不允许把完整游戏写成字符串模板。

核心游戏体验要求：

1. 首页直接进入可玩的街区场景，不要做营销落地页；首次进入时用一个轻量弹窗让玩家填写昵称（可用默认名一键跳过），昵称用于 leaderboard 与成绩标识。
2. 至少准备 5 个关卡、40 个垃圾物品和 4 类垃圾桶：recyclable、compost、hazardous、landfill。
3. 每关有清晰目标，例如“90 秒内正确分类 12 件物品，正确率达到 80%”。
4. 垃圾物品从传送带、地面任务队列或街区角落出现，用户通过拖拽投放到垃圾桶。
5. 正确分类时显示得分、连击、轻量奖励和下一件物品。
6. 错误分类时必须说明正确分类和原因，并把物品加入“待复习”区域，不能只显示“错了”。
7. 支持键盘替代操作：选择物品后按数字键或方向键投放到对应垃圾桶。
8. 每关结束后展示正确率、最高连击、错误清单、学习建议，并同时提供“重玩本关”“进入下一关（若已通关）”和“返回关卡地图”三类入口，成功后的去向必须明确不留死路。
9. 必须包含一个关卡选择/街区地图界面：展示每个关卡的状态（锁定 / 已解锁 / 已通关）、最佳成绩与最高连击，可从这里进入下一关或重玩任意已通关关卡；关卡成功后解锁下一关并回到地图，失败后停留在本关可重玩。
10. 支持 replay 错题关卡，错题关卡必须从 MistakeRecord 派生，不得手写另一份题库；在错题关卡中把某物品分类正确后，对应的 MistakeRecord 必须从“待复习”区移除，待复习区被清空即视为“复盘完成”，形成错题的进入—复盘—消除闭环。
11. 必须包含一个徽章陈列界面：展示全部徽章的已解锁 / 未解锁（灰显）状态和解锁条件说明，可从主菜单或关卡地图进入，让徽章不只有解锁瞬间的反馈。
12. 至少包含一个 boss round：多个相似物品快速出现，需要优先处理危险品。
13. 支持本地假玩家 seed 和当前玩家成绩合并排序的 leaderboard：每关结算时写入/更新当前玩家成绩，结算页与关卡地图都提供查看 leaderboard 的入口，榜单需高亮当前玩家；当前玩家尚无成绩时，显示明确提示。
14. 支持重置进度，并在刷新页面后保留已完成关卡、徽章、昵称和最近成绩。

游戏状态要求：

1. 关卡成功、失败、暂停、结算必须来自 game reducer，不得只依赖 UI 文案。
2. 连击状态不能因为错误复盘、暂停或 replay 面板打开而错误增加。
3. 拖拽取消、拖出视口、放到无效区域必须回到合法状态。
4. leaderboard 排序必须 deterministic，同分时按完成时间和玩家名排序。
5. 徽章包括但不限于“危险品守护者”“连续 10 次正确”“错题复盘完成者”，且一次性徽章不能重复发放；“错题复盘完成者”以待复习区被清空为解锁条件。
6. 360px viewport 下垃圾桶和物品要有大触控目标，文字不能压住游戏区域。
7. prefers-reduced-motion 下减少物品飞入和奖励动画，但游戏仍可完成。
8. 关卡失败后停留在本关并可重玩，关卡成功后解锁下一关；暂停面板必须提供“继续”“重开本关”“返回关卡地图”三个动作，且暂停期间计时与物品生成必须冻结。
9. 重置进度必须同时清空关卡进度、徽章、待复习错题与当前玩家 leaderboard 记录（假玩家 seed 保留），并回到初始可玩状态。

视觉风格与儿童友好设计要求：

1. 面向 6–10 岁儿童：明亮活泼的卡通风格，圆角粗描边、可爱的垃圾桶与物品插画，用 SVG/Canvas 矢量绘制（禁止外部图片），全站保持统一的配色与设计语言。
2. 4 类垃圾桶有稳定可区分的主题色与图标，且不能只靠颜色区分，需同时配图标或文字标签（兼顾色盲）。
3. 字体大号易读、用词口语化；触控目标足够大（建议 ≥ 56px），布局分区清晰不遮挡。
4. 反馈以正向鼓励为主，正确时欢快、错误时温和不惩罚；尊重 prefers-reduced-motion，保证对比度与 focus 可访问性。
