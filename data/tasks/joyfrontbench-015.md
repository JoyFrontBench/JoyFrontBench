请你扮演一名资深游戏化学习产品前端工程师，开发一个完全本地运行的“魔法学院课程、咒语技能树与考试系统”。用户扮演学院学生，按 4 个魔法方向学习咒语节点，完成互动练习提升 mastery，参加分院考试和期末考试，根据结果获得徽章、补习建议和毕业资格。

这不是普通课程列表、静态技能树图片、后台表格或只点按钮加分的 Demo。完成状态必须由可解释的依赖派生、练习结果、考试 rubric、补习路径、徽章幂等、学习日志和持久化学生档案共同证明。

交付形式必须是一个可运行的多文件前端工程，而不是单个 HTML 文件。必须使用 Vite + React + TypeScript。禁止请求在线 AI、远程题库、外部图片、外部字体、付费服务或后端 API；课程、练习、考试、评分和大型展示数据必须 deterministic，同样输入得到同样输出。

## 一、术语与固定规则

1. **学院方向（Track）**：技能分类分支，共 4 个：元素、幻术、炼金、防御。每个 `SpellNode` 归属唯一方向，方向不是学习策略。
2. **咒语节点（SpellNode）**：技能树最小解锁单元，包含方向、前置要求、练习类型、描述和 mastery。
3. **学习路线 / Build 路线（LearningRoute）**：跨方向的学习偏好，例如专精元素、偏防御、均衡发展。路线只影响推荐/高亮，不改变任何 mastery、掌握状态、徽章或日志。
4. **经验与 mastery**：本题中二者为同一数值维度，每个节点维护 `0..100` mastery。练习或考试奖励只能增加 mastery，不得低于 0 或超过 100。
5. **掌握（mastered）**：当节点 mastery 达到 `MASTERED_THRESHOLD` 时判定为 mastered，且一经 mastered 不因路线切换、考试失败、重算或刷新而回退。

固定阈值和权重必须写为常量并在 README 说明：

- `PREREQ_THRESHOLD = 60`：全部前置节点 mastery ≥ 60 才能解锁后继。
- `MASTERED_THRESHOLD = 100`：mastery 达到 100 判定 mastered。
- `HOUSE_EXAM_PASS = 70`：分院考试及格线，总分满分 100。
- `FINAL_EXAM_PASS = 82`：期末考试及格线，总分满分 100。
- `REMEDIAL_THRESHOLD = 80`：考试未通过时，考试范围内 mastery < 80 的节点进入补习路径。
- rubric 权重固定为：准确率 40、速度 25、策略 20、失误 15，合计 100。
- 单次练习 mastery 增量使用确定性公式：`score × 0.55 + speedBonus − mistakePenalty`，并设置不低于 12 的正反馈下限；如系数微调，必须在 README 写明且单测覆盖。

## 二、工程结构

1. 必须包含 `package.json`、`index.html`、`src/main.tsx`、`src/App.tsx`、`README.md`。
2. `package.json` 至少提供 `npm run dev`、`npm run build`、`npm run test`、`npm run typecheck`；`npm run lint` 为 SHOULD。
3. 至少定义 `StudentProfile`、`Course`、`SpellNode`、`Prerequisite`、`PracticeAttempt`、`ExamSession`、`RubricResult`、`Achievement`、`LearningRoute`、`LearningLogEntry` 等 TypeScript 类型。
4. 至少拆分以下职责模块：
   - 学生档案、方向、课程、咒语节点、考试和路线 seed 数据；
   - 技能树依赖、循环检测、节点状态派生、路线推荐；
   - 三类练习交互、得分计算、mastery 更新和学习日志；
   - 考试 session、rubric breakdown、补习路径、徽章幂等解锁；
   - 技能树画布/列表、节点详情、练习面板、考试结果、进度概览和日志组件；
   - localStorage 持久化、schema version、reset student、坏值逐字段回退和旧日志迁移。
5. 推荐目录：`src/components/`、`src/components/tree/`、`src/components/practice/`、`src/domain/`、`src/state/`、`src/data/`、`src/hooks/`、`src/utils/`、`src/test/`。
6. 技能树依赖、循环检测、经验计算、考试评分、徽章解锁、补习路径和路线推荐必须放在可测试的纯函数或 reducer 中，React 组件不得复制核心规则。
7. 不允许使用 `dangerouslySetInnerHTML`，不允许把完整页面或大段组件写成字符串模板。

## 三、固定数据规模与技能树

1. 必须提供 4 个方向，每个方向 6 个节点，总计 24 个 `SpellNode`。
2. 每个节点至少包含：稳定 id、名称、方向、tier/层级、描述、练习类型、前置节点 id 列表、推荐路线权重或标签。
3. 每个方向至少有 1 个起始节点、2 个中层节点、1 个高阶节点；跨方向前置可以存在，但必须在 UI 和数据中清楚解释。
4. 技能树数据加载时必须检测循环依赖；发现环时必须显示可理解错误或安全降级，禁止无限递归或空白页。
5. 节点状态由纯函数根据当前 `StudentProfile` 与依赖关系派生，固定为四态之一：
   - `mastered`：mastery ≥ 100；
   - `recommended`：已解锁且符合当前路线下一步建议；
   - `unlocked`：全部前置 mastery ≥ 60，但当前不是推荐；
   - `locked`：仍有前置未满足。
6. 四态必须有文字或图标/描边辅助，不得只靠颜色区分。

## 四、核心界面与视觉方向

1. 首屏必须直接呈现魔法学院技能树工作台：技能树主视图、节点详情/练习区、进度/考试/徽章侧栏或等价布局；不要做营销 hero 或普通课程卡片墙。
2. 桌面端应提供可缩放、可平移的 SVG 或 Canvas 技能树画布，节点连线表达前置依赖；如果使用列表替代，必须仍能展示依赖关系和路径高亮。
3. 移动端 390×844 左右可降级为按方向分组的折叠列表，但节点状态、解锁规则、练习、考试、补习跳转与桌面一致。
4. 点击节点必须展示详情：名称、方向、当前 mastery、四态、前置要求、解锁说明、练习类型、推荐原因、相关徽章或补习状态。
5. 整体风格为“魔法学院星象/秘卷”：深靛夜空或秘卷背景、发光节点、连线星轨、方向主题色和金色掌握态；禁止呈现为普通后台表格、低质课程列表或无差别玻璃卡片。
6. 四方向建议色系：元素=琥珀橙、幻术=紫罗兰、炼金=翠绿、防御=青蓝；掌握态用金色强调，锁定态降低饱和度并保留文字说明。
7. 动效必须服务于反馈：节点解锁、mastery 提升、徽章获得、补习跳转可有短暂发光/描边；必须尊重 `prefers-reduced-motion`，开启后禁用非必要动画。
8. 所有按钮、节点、考试入口、路线切换和补习链接要有 hover、active、focus-visible 和 disabled 状态。

## 五、三类练习与 mastery 更新

必须提供至少三种互不相同的练习类型，每种练习都要有真实交互、确定性评分和可解释结果：

1. **符文排序**：用户按正确顺序排列或选择符文序列；评分体现顺序正确率和失误数。
2. **元素调配**：用户选择元素配比或配方组合；评分体现目标配比误差和策略匹配。
3. **防御反应**：用户针对攻击/事件选择防御动作或时机；评分体现反应选择、速度奖励和失误。

练习要求：

1. 只能对 `unlocked` 或 `recommended` 节点练习；locked 节点必须解释缺少哪些前置。
2. 完成练习后显示：练习类型、score、speedBonus、mistakePenalty、最终增量、当前 mastery、是否解锁后继。
3. 更新必须立即反映到技能树、节点详情、进度概览、推荐节点、徽章和学习日志。
4. 每次练习写入稳定日志条目，包含 event id、节点 id、练习类型、得分、增量和时间标签。时间标签可用 deterministic 递增序号，避免依赖当前系统时间。
5. 同样初始状态与同样输入必须得到同样 score 与 mastery 增量。

## 六、学习路线、推荐与进度概览

1. 至少提供三条路线：专精元素、偏防御、均衡发展；可额外加入幻术/炼金路线。
2. 路线切换只改变推荐节点、高亮和推荐解释，不改变已掌握节点、mastery、徽章或日志。
3. 推荐逻辑必须可解释：显示为什么某节点被推荐，例如“当前路线偏防御、前置已满足、mastery 较低”。
4. 进度概览至少显示：总体掌握度、四方向进度、已掌握节点数、已获徽章、下一步推荐节点、最近学习日志。
5. SHOULD 展示“近期进步”指标，并在 README 说明计算窗口，例如最近 5 次事件 mastery 增量之和。

## 七、考试系统、补习路径与毕业资格

1. 必须提供分院考试：用户选择单一方向后考试，考试范围只包含该方向相关节点。
2. 必须提供期末考试：跨方向综合考试，覆盖全部方向或每方向代表性节点。
3. 每次考试生成 `ExamSession`，并展示 rubric breakdown：准确率、速度、策略、失误四维原始分、权重、加权分、总分、通过/失败结论。
4. 分院考试及格线固定 70；期末考试及格线固定 82；边界分数必须准确处理。
5. 考试评分 deterministic，不得用随机数决定通过/失败。
6. 考试未通过时必须生成补习路径：从本次考试范围中筛选 mastery < 80 的相关节点；mastery 等于 80 不纳入。
7. 补习路径每项显示节点、方向、当前 mastery、缺口和建议练习；点击必须跳转到技能树对应节点、打开详情并短暂高亮，不得改变业务状态。
8. 补习后重考必须使用最新 mastery 重新评分和重算补习路径。
9. 期末通过可触发毕业资格或毕业徽章；未通过不得错误授予。

## 八、徽章、日志与幂等性

1. 至少提供 6 个徽章，覆盖首次练习、某方向全 mastered、三类练习都完成、分院考试通过、期末通过、连续学习或均衡发展等条件。
2. 徽章解锁必须幂等：同一徽章重复触发只保留一条 achievement，不重复计数或重复日志。
3. 徽章应显示解锁条件、解锁状态和获得来源。
4. 学习日志至少记录练习、考试、徽章解锁、reset；按最新事件优先或明确顺序展示。
5. reset student 后进度、徽章、日志、路线和选择状态恢复初始档案。

## 九、持久化与坏值恢复

1. 使用 localStorage 保存 schema version、student profile、mastery map、achievements、route、learning log、当前选中节点、考试摘要或最近结果。
2. 刷新后必须恢复 mastery、徽章、路线、日志和技能树状态；不要求恢复 transient 动画。
3. 读取持久化数据时必须校验字段缺失、类型错误、未知节点 id、越界 mastery、重复徽章、坏日志和错误版本。
4. 坏值必须逐字段回退：合法字段尽量保留，坏字段回到默认值；不得因局部坏值丢弃整个学生档案，除非根结构完全不可用。
5. 旧版字符串日志或缺少字段的日志应迁移到新结构，或以可理解方式过滤并提示。
6. reset student 必须清空持久化并恢复初始档案，刷新后仍保持初始状态。
