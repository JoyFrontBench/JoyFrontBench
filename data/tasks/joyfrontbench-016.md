一级分类：网页 / 业务界面
二级分类：官网界面

请你扮演一名资深创意前端工程师，擅长高端 WebGL 产品展示、React 工程组织、动效系统和可维护视觉工程。请为一个虚构可乐品牌制作一个高级、沉浸、具有强烈产品视觉中心的品牌营销落地页。页面可以借鉴经典红色可乐广告的能量感，但不能使用外部图片、外部 3D 模型或复制真实品牌素材。

交付形式必须是一个可运行的多文件前端工程，而不是单个 HTML 文件。技术栈要求如下：
1. 必须使用：Vite + React + TypeScript 作为工程框架；Three.js 实现 3D 场景；GSAP（含 ScrollTrigger）实现滚动动画；Vitest 编写单元测试。
2. 可选使用：Tailwind、CSS Modules 或普通 CSS 任选其一实现样式；Playwright 用于端到端测试。
3. 所有依赖均通过 npm 安装。允许 npm 安装和构建，但禁止 API 请求、外部图片下载、HDR 贴图、GLB/OBJ/FBX 模型、真实品牌素材和远程运行时数据。

工程结构要求：
1. 必须包含 package.json、index.html、src/main.tsx、src/App.tsx、README.md。
2. package.json 至少提供：
- npm run dev
- npm run build
- npm run test（仅运行 Vitest 单元测试，不依赖浏览器）
- npm run lint 或 npm run typecheck
3. 至少拆分出以下职责模块，不要把主要逻辑堆在 App.tsx：
- 主题 tokens、主题数据和主题状态
- 导航栏、主题分段控件和 shake 控制组件
- Hero、marquee、风味层次、工艺与配料、限定发售组件
- Three.js 场景初始化和生命周期管理
- 程序化易拉罐几何体创建
- Canvas 标签纹理绘制与纹理更新
- 粒子系统、气泡爆发、冷凝水滴和摇动交互
- GSAP ScrollTrigger 注册、清理和 reduced-motion 降级
- localStorage 持久化 hook 或工具
- prefers-reduced-motion hook 或工具
- WebGL 资源追踪与 dispose 工具
5. Three.js 模块必须导出清晰的 SceneController，至少包含 init、start、stop、resize、setTheme、shake、setPointerTarget、setDragging、setInspect（进入/退出检查模式，控制暂停自转与放大）、dispose 方法。组件卸载时必须释放 renderer、geometry、material、texture、animation frame、事件监听、GSAP timeline 和 ScrollTrigger 实例。
6. Canvas 标签纹理必须是独立模块，输入主题配置、产品版本和绘制参数后返回可复用 texture 或更新函数。
7. 主题配置必须是结构化数据，不允许在多个组件中散落硬编码颜色。CSS 变量必须从同一份主题数据映射而来。
8. 类型定义要清晰，关键 ThemeConfig、CanSceneController、CanPart、LabelTextureOptions、ParticleBurstOptions、InteractionMode、ReducedMotionState 要有 TypeScript 类型。其中 InteractionMode 至少覆盖 idle / dragging / shaking / inspect 四态。
9. 不允许使用 dangerouslySetInnerHTML，不允许把完整页面或大段组件写成字符串模板。

设计风格与审美要求：
1. 整体风格定位：当代高端碳酸饮料品牌的电影感产品广告，暗色为主的沉浸式舞台氛围，强产品视觉中心，气质克制、精致、有分量感与真实产品可信度。应体现：舞台聚光、金属质感、清晰视觉焦点、干净的排版秩序。应避免：卡通扁平插画、廉价促销风、花哨炫技、杂乱堆叠、儿童向配色。
2. 版式与排版系统：
- 建立清晰的排版层级，至少区分 Hero 主标题、区块标题、正文、辅助说明和标签微字五级，层级之间字号与字重对比要明显。
- 字体只能使用系统字体栈，或通过 npm 依赖打包进构建的本地字体；禁止运行时远程加载字体（与禁止远程数据保持一致）。建议正文用高可读无衬线字体，大标题可用更具个性的展示字型。
- 使用统一的间距刻度（例如以 4px 或 8px 为基数）、统一的圆角、边框宽度和阴影层级 token，全站排版节奏一致。
3. 配色语言：每个主题必须定义一组结构化、角色化的颜色，至少包含背景基色（含深浅层次）、表面 / 面板色、正文文字色、次要文字色、主强调色、次强调色、边框 / 分隔色、灯光色和粒子色；所有颜色来自同一份主题数据。整体走高对比、有明确焦点的配色，不使用大面积低对比灰调。
4. 三种主题的审美个性（必须彼此可辨识，又统一在同一设计系统下）：
- 经典红：深色舞台配炽热红主强调，暖调聚光，情绪热烈自信；罐体金属反射偏暖光。
- 零糖黑：近黑背景配银 / 冷白 / 微蓝强调，光感干净锐利，气质冷冽、极简、现代；罐体偏镜面冷光。
- 柑橘限定：更明快通透的背景层次配橙 / 黄绿强调，光感清新、情绪年轻愉悦，但仍需保持高级感，避免变成廉价的高饱和橙。
- 三个主题必须共享同一套版式、间距和组件结构，仅通过颜色、灯光、材质和标签体现差异，做到“同一设计系统的三种皮肤”。
5. 材质与质感语言：
- 铝罐：具真实感的金属材质，有清晰高光、菲涅尔边缘反光和可控的磨砂 / 镜面程度；不同主题金属色温不同。
- 玻璃拟态面板：适度背景模糊、半透明表面、约 1px 的亮边框和克制的阴影 / 内发光，保持通透高级、不糊成一片；仅用于面板和控制组件。
- 背景：可使用细腻噪点、精细网格或扫描线、暗角与聚光营造舞台深度；禁止渐变光球和模糊色块。
6. 光影与氛围：以聚光灯打在产品上的舞台布光为核心，罐体有清晰高光与反射，场景带有深度暗角；灯光颜色随主题变化并与配色协调统一。
7. 动效性格：整体高端、克制、有重量感与顺滑惯性，缓动以缓入缓出或带轻微 overshoot 的弹性为主，避免生硬线性、夸张弹跳或廉价闪烁；动效始终服务于产品聚焦，不喧宾夺主（具体时长与降级见布局和动画要求、性能要求）。
8. 图形与装饰细节：使用统一的工业 / 技术感细节语言（批次号、刻度线、细分隔线、编号、单位小字等）强化真实产品的可信度；所有装饰必须服务于信息或质感，不做无意义炫技。
9. 三种主题参考色值（下列 hex / rgba 为参考基准，实现可在同一色相区间内微调，但必须保持三主题彼此可辨识，且正文与背景满足 WCAG AA 对比度）：
- 经典红：背景基色 #140406（更深层 #0D0304、面板 #241012 半透明）；正文 #FDECEC；次要文字 #C89A9A；主强调 #E01823；次强调（暖金）#E8A33D；边框 rgba(255,180,180,0.15)；灯光暖白 #FFE3D0；粒子 #FF5A4D / #E8A33D。整体暖调、热烈、自信。
- 零糖黑：背景基色 #0A0C10（更深层 #06080B、面板 #12161E 半透明）；正文 #EEF2F6；次要文字 #9AA4B0；主强调（冷银）#C0C8D0；次强调（电蓝）#3FA0F0；边框 rgba(180,200,220,0.14)；灯光冷白 #EAF1F8；粒子 #C0C8D0 / #4DA6FF。整体冷冽、锐利、极简、现代。
- 柑橘限定：背景基色 #1A0E03（更深层 #120A02、面板 #241505 半透明）；正文 #FBF3E6；次要文字 #D9C3A5；主强调（柑橘橙）#FF8A2B；次强调（青柠黄绿）#B6D94A；边框 rgba(255,200,140,0.16)；灯光暖橙白 #FFEBCC；粒子 #FF8A2B / #B6D94A。整体明快、通透、年轻，但饱和度需克制、不廉价。
10. 设计系统 token 清单：主题数据必须映射为一组集中定义的 CSS 变量，至少包含下列变量（命名可微调但需语义清晰、集中定义、不得散落硬编码）；其中所有 --color-* 变量必须随主题切换平滑更新：
- 颜色：--color-bg、--color-bg-deep、--color-surface、--color-text、--color-text-muted、--color-accent、--color-accent-2、--color-border、--color-light、--color-particle、--color-marquee
- 间距（基于 4px 或 8px 刻度）：--space-1 到 --space-6
- 圆角：--radius-sm、--radius-md、--radius-lg
- 阴影：--shadow-sm、--shadow-md、--shadow-lg
- 排版：--font-display、--font-body，以及 --text-hero、--text-title、--text-body、--text-caption、--text-micro 五级字号
- 动效：--ease-standard、--ease-emphasized、--transition-theme（主题切换的过渡时长与缓动）

核心体验要求：
1. 首屏必须是电影感产品 Hero，中心放置程序化生成的 3D 易拉罐。
2. 易拉罐必须完全用 Three.js 程序化几何体构建，允许使用 Three.js 内置几何体（如 CylinderGeometry、LatheGeometry、TorusGeometry、CircleGeometry、SphereGeometry、BoxGeometry 等）及其组合，或用 BufferGeometry 程序化生成；禁止导入任何外部模型文件。罐体细节至少包括罐身、顶部边缘、底部边缘、拉环、拉环孔、铆钉、倒角唇边、顶部内凹、底部凹槽、罐身竖向高光、冷凝水滴和细腻金属反光。
3. 不允许导入任何外部模型、图片、HDR 或远程贴图；环境反光可以用程序化 Canvas/CubeTexture 或灯光模拟。
4. 冷凝水滴要分布在罐身可见区域，大小、透明度、拉伸方向有变化；主题切换和 shake 后不能丢失。
5. 易拉罐标签必须用 HTML Canvas 动态绘制并作为纹理贴到罐身上。标签里要包含自定义手写风格字标、产品版本文案、装饰线条、类似营养信息的小字、批次编号、重复细节纹理和可见罐身接缝细节。
6. 标签绘制要支持确定性随机种子，刷新页面后同一主题的细节稳定，不要每次随机乱跳。
7. 实现三种主题模式：
- 经典红
- 零糖黑
- 柑橘限定
8. 切换主题时，页面背景、正文颜色、边框、灯光、粒子颜色、易拉罐材质、Canvas 标签纹理和 marquee 颜色都要平滑过渡。
9. 用户选择的主题要存入 localStorage，刷新页面后自动恢复；localStorage 坏值不能导致页面崩溃。

高级交互要求：
1. 易拉罐在空闲状态下要缓慢自转。
2. 鼠标移动、触摸移动或键盘方向键操作时，易拉罐要带有弹性缓动地轻微倾斜。
3. 用户可以拖拽易拉罐进行手动旋转；拖拽期间自动旋转暂停，松手后根据惯性短暂续转，再平滑回到自动旋转状态。点击罐体（无明显拖拽位移）不触发其他模式，避免与检查模式冲突。
4. 增加一个“摇一摇”按钮：点击后易拉罐短暂震动，粒子活跃度提高，并释放一小段 3D 气泡爆发效果。
5. shake 按钮在 1.2 秒内要防止重复触发，按钮要有可见 busy/disabled 状态，但 reduced-motion 下仍要给出可感知反馈。
6. 主题切换器必须使用分段控件，不要做成普通文字按钮。
7. 主题切换器、“摇一摇”按钮和“检查模式”控件都要支持键盘操作、ARIA 状态和清晰 focus 状态。
8. 增加一个“产品检查模式”，通过一个独立、可见的“检查模式”控件（按钮或图标按钮）触发，不通过点击罐体触发，以避免与拖拽旋转冲突：激活后易拉罐暂停自转并放大到可检查角度；再次点击该控件或按 Escape 返回沉浸式自动展示。该控件需支持键盘操作（Enter/Space 激活）、ARIA 状态（如 aria-pressed）和清晰 focus 状态。检查模式不能遮挡主题控件。
9. 易拉罐交互状态机为互斥四态：idle（缓慢自转）、dragging（拖拽旋转，自转暂停，松手后惯性续转再回到 idle）、shaking（摇一摇动画期间，冷却结束后回到 idle）、inspect（检查模式，暂停自转并放大，退出后回到 idle）。dragging、shaking、inspect 三态互斥，状态转换必须无歧义、无死锁；处于 inspect 或 dragging 期间触发 shake 时，按第 5 条的防抖 / 禁用规则处理。

布局和动画要求：
1. 页面启动时要有加载页，加载页像幕布一样向上揭开，并带有进度指示，不要硬切到主页面。
2. Hero 区域必须是全屏沉浸式体验，产品要清晰可见，不能被塞进装饰卡片里。
3. 添加 sticky 玻璃质感导航栏，页面滚动后导航栏密度、阴影和边框样式要发生变化。
4. 添加一个无限横向滚动的 marquee 文案条，并且文案颜色要跟随主题变化。
5. Hero 后至少包含三个内容区：
- 风味层次
- 工艺与配料
- 限定发售
6. 使用 GSAP ScrollTrigger 实现滚动进入动画、视差文本移动、产品固定展示片段和内容区逐段高亮。
7. reduced-motion 模式下必须关闭非必要连续动画、ScrollTrigger scrub 和大幅位移，但仍保留内容可见、主题切换、拖拽、检查模式和 shake 基础反馈。
8. 玻璃拟态只能用于具体内容面板和控制组件，不要把整个页面区块都做成悬浮卡片。

性能和稳定性要求：
1. Three.js 渲染循环不能触发 React 高频 setState。
2. renderer pixelRatio 要设置上限，移动端不能无限使用 devicePixelRatio。
3. resize 要节流或用 ResizeObserver 合理处理，不能在窗口尺寸变化时疯狂重建场景。
4. 加载幕布应由真实加载 / 初始化进度驱动，并设一个最小可感知时长（约 600ms）以展示进度；一旦资源就绪即揭开，且总时长不得超过 3 秒。
5. 页面不能有明显布局跳动；3D 视口、主题控件、卡片、marquee 和按钮都要有稳定尺寸。
6. 控制台不能有运行时报错、资源 404、React key 警告或 Three.js dispose 后访问错误。

视觉质量要求：
1. 页面必须适配 360px 宽移动屏幕到宽屏桌面。
2. 任何文字都不能重叠、溢出或被按钮/卡片裁切。
3. 3D 产品在桌面和移动端都必须清晰可见，不能只露出边缘或被 UI 遮挡。
4. 每个主题下文字都要满足 WCAG AA 对比度（正文 ≥ 4.5:1，大字号或图形元素 ≥ 3:1）。
5. 不要使用装饰性渐变光球、模糊色块或 SVG Hero 插画。
6. 视觉资产必须来自代码生成、Canvas 或 Three.js 程序化绘制。
