一级分类：数据可视化
二级分类：博弈模拟可视化

请实现一个「石头剪刀布 AI 训练可视化 Dashboard」。页面以石头剪刀布为轻量互动素材，让用户通过连续出拳观察一个本地模拟 AI 的预测、置信度、策略解释、历史统计与回放。本题的难度不在预测算法，而在前端信息架构、图表联动、时光回溯回放、筛选派生统计一致性与大数据量下的流畅度——这些是数据型前端产品最易失分的地方。

交付一个可运行的 Vite + React + TypeScript 多文件前端工程，不要提交单个 HTML。禁止调用真实在线模型、外部 AI 服务、远程 API、远程图片或不可复现随机数。所谓"AI"仅指本地 deterministic 规则模拟：用频率统计、最近转移、固定 seed 的探索策略生成预测数据，用来驱动界面展示，算法本身不作为主要考查点。

## 工程要求

1. 必须包含 `package.json`、`index.html`、`src/main.tsx`、`src/App.tsx`、`README.md`。
2. `package.json` 至少提供：`npm run dev`、`npm run build`、`npm run test`、`npm run typecheck`。
3. 代码需拆分为清晰模块，至少覆盖：
   - RPS 胜负规则与回合记录
   - 本地 AI 模拟器（预测分布、解释文案、策略标签）
   - session / mode / challenge / replay 状态 reducer
   - 每回合快照（snapshot）与历史派生、筛选、统计
   - 导出导入与 localStorage 恢复
   - 出拳区、AI 状态卡、训练图表、历史表格、replay 控制、设置区
4. 胜负判定、统计计算、筛选排序、快照重建、replay、持久化恢复必须放在可测试的纯函数或 reducer 中。
5. 不允许使用 `dangerouslySetInnerHTML`，不允许把完整页面写成大段字符串模板。

## 页面与核心体验

1. 首屏应像一个训练分析工作台。建议桌面端分为：左侧出拳/挑战，中间 AI 状态与预测分布，右侧训练图表与历史。
2. 用户可点击 rock / paper / scissors 出拳；每回合记录玩家出拳、AI 出拳、胜负结果、AI 赛前预测分布、策略标签和置信度。
3. 页面同时展示：当前 mode（best of 15 / endless）、AI 状态卡（策略标签、最高预测项、置信度、解释文案、最近一次是否命中）、预测分布图（三项合计为 1 或 100%）、最近序列、玩家胜率/AI 胜率/平局率/最长连胜/预测命中率、挑战进度与结算状态。
4. 支持 best of 15 与 endless。best of 15 第 15 回合后结算并禁止继续出拳，除非 reset。
5. 支持"欺骗 AI"挑战：连续 5 回合避开 AI 赛前最高预测则完成，命中则清零，进度有明确视觉反馈。
6. 训练视图可展开或收起，展开后至少含三类图表：预测命中/未命中时间线、置信度变化、策略标签时间线；数据来自真实 rounds。

## 重点难点要求

以下机制是数据型前端产品的高频失分点，请确保正确：

1. **每回合快照与时光回溯**：每一回合都要保存"当时"的快照，至少包含该回合赛前的预测分布、策略标签、置信度、以及截至该回合的统计与挑战进度。提供一条可拖动的 replay 时间轴 scrubber，用户拖动到任意回合时，整个 dashboard——统计卡、三类图表、AI 状态卡、挑战进度、最近序列——都要重建为"那一回合当时"的状态。
   - AI 状态卡在回溯时显示的必须是该回合**赛前快照**（预测该回合玩家出什么），不是用全量历史重新计算的当前值。
   - 回放控制还需支持：播放、暂停、单步上一/下一回合、回到开头/跳到最新、显示当前回放位置（第 k / N 回合）。
2. **多图表与表格联动**：在任一图表上 hover 或在时间轴上 scrub 时，三类图表与历史表格要高亮同一回合，共享十字准线/竖线与 tooltip，展示该回合的关键字段；移出后恢复。
3. **历史表格筛选、排序与派生统计一致**：历史表格支持按结果（玩家胜/AI 胜/平局）、策略标签筛选，并可按回合号、置信度、结果排序。关键约束：
   - 展示筛选结果条数（可使用等价的清晰标签），其数值等于当前筛选后历史表格的行数；预测命中率仍按筛选子集中的预测命中回合计算，两者不可混用；
   - 统计卡中的胜率、命中率等派生指标在存在筛选时应基于**当前筛选子集**重算，并明确标注是"筛选后"还是"全局"，不能筛选后仍显示全局旧值；
   - 筛选、排序、筛选结果数、派生统计四者必须一致，不出现"表格变了统计没变"。
4. **大数据量下的流畅度**：endless 模式连续出拳到 300 回合以上时，历史表格与图表仍需流畅（可用表格虚拟化、图表降采样或增量更新），滚动、筛选、scrub 无明显掉帧或卡死；若做降采样需保证 hover/scrub 定位到的仍是真实回合数据。

## 数据、恢复与 replay

1. Reset 必须清空 round history、快照、AI 状态、统计、筛选条件、挑战状态、结算状态、replay 位置和持久化草稿。
2. 快速连点不能重复提交同一回合；按钮应有短暂 lock 或 reducer guard。
3. session 保存到 localStorage；reload 后显示恢复/丢弃选择。坏值、旧版本值或缺字段不能白屏，应回退到初始状态。
4. 支持导出 JSON，字段至少含 mode、seed、rounds、filters，以及每回合 player/ai/predicted/result/strategy/confidence/explanation 与赛前快照信息，足以复现回放与时光回溯。
5. 支持导入 JSON 并回放；replay 与时光回溯不得重新随机 AI 出拳，必须复现导出记录中每回合的 AI 选择、赛前快照、结果与统计。
6. 不得依赖预先提供的回放文件；你必须让实现或自动化测试用固定 seed session 自行生成并导出 replay JSON，再导入同一文件验证完整复现。

## 本地 AI 模拟规则

1. 至少三种可区分策略标签：`frequency`（累计频率）、`sequence`（最近转移）、`explore`（固定 seed/回合号驱动）。
2. 每轮先用当前历史生成赛前预测并保存为该回合快照，再决定 AI 出拳，最后更新历史。
3. 预测分布来自 session 数据、合计正确、不写死；`explore` 不得用不可复现随机数。
4. 每回合保存解释文案，说明当前策略与预测来源。

## 视觉与响应式

1. 图表用 SVG / Canvas / DOM 实现均可，但数据必须来自真实 rounds。
2. 历史表格桌面端有清晰列结构，移动端可折叠为卡片列表。
3. 360px viewport 下可出拳、查看预测分布、挑战进度、统计卡、最近回合，并可访问 replay 与时光回溯（可简化控件但功能不缺）。
4. `prefers-reduced-motion` 下减少动画但不隐藏状态变化。
