一级分类：演示 / 概念可视化
二级分类：仿真模拟（非3D）

请你扮演一名资深可视化前端工程师，擅长参数化动画、直接操作交互、本地物理近似与可测试 simulation state。请实现一个「液体倾倒物理动画实验台」：用户选择容器与液体，倾斜容器倒出液体，观察液面变化、水流轨迹、飞溅、命中、溢出与液面累积。本题的难度不在美术，而在物理行为的正确性——很多实现会用假物理蒙混过关，本题要求这些行为在画面与数据上都真实、可配置、可复现、可测试。

交付形式必须是一个可运行的多文件前端工程，而不是单个 HTML 文件。请使用 Vite + React + TypeScript 实现；SVG、Canvas、Pointer Events、Vitest 与 Playwright 均可通过 npm 依赖引入。系统不要求真实 Navier-Stokes 流体力学，但必须是可解释、可配置、可测试的确定性近似模型；禁止远程图片、物理服务、外部模拟 API 或不可复现随机结果。

## 工程结构要求

1. 必须包含 package.json、index.html、src/main.tsx、src/App.tsx、README.md。
2. package.json 至少提供 npm run dev、npm run build、npm run test、npm run lint 或 npm run typecheck。
3. 至少拆分出以下职责模块：
   - 容器、液体类型、倾倒参数、粒子和接收杯数据
   - 液面几何、出水判定、水流轨迹、命中检测、体积守恒和 overflow 判断
   - simulation tick、pause/resume/reset、慢动作和 RAF 清理
   - preset 保存、preset 对比和实验统计派生
   - 容器可视化、液面/水流/飞溅、接收杯、参数控件和实验报告组件
5. 至少定义 Vessel、LiquidState、PourParameters、StreamParticle、ReceiverState、SpillEvent、SimulationFrame、PourPreset 等 TypeScript 类型。
6. 液面几何、出水判定、水流轨迹、落点、命中、接收杯累积、溢出判定和统计计算必须放在可测试的 simulation/domain 模块中。
7. 不允许使用 dangerouslySetInnerHTML，不允许把完整页面或大段组件写成字符串模板。

## 核心体验要求

1. 页面必须是可操作的实验台，不得只画一张静态"倒水"SVG 或普通参数表。
2. 支持至少 4 种容器：茶壶、烧杯、碗、量杯；不同容器有不同的容量、壶嘴/倾倒口位置。
3. 支持至少 3 种液体：水、蜂蜜、糖浆；粘度必须真实影响流速、水流形态和落点。
4. 用户可以选择容器和液体类型，并通过拖动容器旋转或滑杆调整倾斜角，倾斜时容器与内部液体的表现要同步、正确。
5. 用户可以拖动接收杯位置，命中判断随拖动实时更新。
6. 点击 Start Pour 后开始倒液；支持 pause、resume、reset 和慢动作。
7. 显示本次实验数据：倒出量、接住量、溢出量、效率、平均流速和体积误差。
8. 支持保存一个实验 preset，并比较两个 preset 的倾倒效率，对比数据必须来自真实 simulation。
9. 360px viewport 下可完成容器选择、倾倒、移动接收杯和查看统计。

## 物理正确性要求（本题区分度核心，务必满足）

以下行为是本题的重点，很多实现会用固定曲线或线性公式造假，请确保在画面与数据上都真实：

1. **液面随重力保持水平**：无论容器倾斜到什么角度，容器内液体的自由表面必须始终保持水平（相对屏幕/重力方向），而不是随容器一起旋转。倾斜时液面与容器壁的相交形状会变化。
2. **出水条件由液面与倒倾口的几何关系决定，而非固定角度阈值**：是否出水取决于"当前倾角下，水平液面是否已经到达并越过容器的倾倒口"。因此：容器越满，越小的倾角就开始出水；容器越空，需要越大的倾角才能出水。倒的过程中随着液体减少，若倾角不变，出水会逐渐变慢直至停止，需要继续加大倾角才能维持出水。
3. **水流按抛物线轨迹下落**：液体离开倾倒口后按抛物线运动（受离口速度与重力影响），落点由物理关系决定；改变倾角、倒倾口高度或流速时，抛物线形状和落点应随之连续变化，不能是写死的贝塞尔曲线或"落点 = 角度×常数"这类线性公式。
4. **粘度影响水流形态与轨迹**：低粘度（水）水流细、离口速度大、抛物线更远更平；高粘度（蜂蜜、糖浆）水流粗、慢、接近垂直下落，并可在流速很低时断续成滴而非连续流。
5. **命中随落点实时判断**：当拖动接收杯或改变倾角/流速导致落点移动时，命中/未命中要实时更新；落在接收杯口内为命中，否则未命中。
6. **冲击飞溅确定性可复现**：水流击中接收杯液面或台面时产生飞溅粒子，飞溅的方向、幅度与流速/落点相关，且必须由确定性规则生成（相同参数与帧序列产生相同飞溅），不得用不可复现随机数。
7. **接收杯内液面同样水平并累积**；接收杯装满后继续命中应产生 overflow，溢出液体在台面形成 puddle，puddle 随累计溢出量增大。
8. **体积守恒可验证**：倒出量 = 接住量 + 溢出量 + 台面 spill 量 + 容器残余误差，误差应接近 0；容器剩余量不得为负。

## 模拟与稳定性要求

1. Pause 后 simulation frame 不得继续推进。
2. Reset 必须清空粒子、容器液面、接收杯液面、统计、溢出事件、puddle 和运行状态，并回到可重新实验的初始参数。
3. 快速 Start/Pause/Reset 不得创建多个 RAF 或 timer。
4. 参数非法输入要被 clamp 或拒绝，不能出现 NaN、负体积、无限流速或落点跳变。
5. 相同容器、液体、倾角轨迹与慢动作设置下，两次运行的水流轨迹、命中、溢出与统计必须完全一致（确定性）。
6. reduced-motion 下可用离散帧更新替代高频粒子/飞溅动画，但液面几何、出水判定与统计仍需正确、可验证。
7. 控制台不能出现运行时报错、资源 404、React key 警告或未处理 Promise rejection。
