一级分类：演示 / 概念可视化
二级分类：仿真模拟（非3D）

请你扮演一名资深工程教育前端工程师，擅长机械运动模拟、参数化几何、多体同步动画与可测试 simulation tick。请实现一个「直列四缸四冲程发动机剖面工作台」：用户观察四冲程发动机的进气、压缩、做功、排气过程，调节转速、曲柄半径、连杆长度、余隙与点火提前角，看到活塞、连杆、曲轴、气门升程、火花、压力曲线与 P-V 示功图同步变化，并能对比参数方案。本题基础的曲柄连杆运动学并不难，难度在于把压力/容积/气门/多缸相位真正耦合起来——很多实现会用"装饰性压力高斯 + 二元气门 + 单缸"蒙混，本题要求这些在几何与数据上都自洽、可复现、可测试。

交付形式必须是一个可运行的多文件前端工程，而不是单个 HTML 文件。请使用 Vite + React + TypeScript 实现；SVG、Canvas、Vitest 与 Playwright 均可通过 npm 依赖引入。禁止使用远程图片、真实硬件、外部物理 API 或不可复现随机数据；本题是机械运动教学模拟，不得做成静态剖面图、普通参数表或只播放 CSS keyframes。

## 视觉与场景风格

1. 采用工程技术手册/蓝图剖面风：干净的示意剖面、清晰标注、仪表化读数，工程感强而不杂乱。
2. 活塞、连杆、曲轴、气门、火花塞、压力曲线与 P-V 示功图需有清晰视觉层级与图例，一眼看懂各部件与当前冲程。
3. 是可实时交互的模拟，不是静态插图。

## 工程结构要求

1. 必须包含 package.json、index.html、src/main.tsx、src/App.tsx、README.md。
2. package.json 至少提供 npm run dev、npm run build、npm run test、npm run lint 或 npm run typecheck。
3. 至少拆分出以下职责模块：
   - 发动机参数、曲柄状态、活塞状态、气门升程、压力/容积样本与多缸配置数据
   - crank-slider 几何、相位判定、气门升程与正时、容积计算、压力-容积耦合与示功图计算
   - simulation tick、RPM 转换、Play/Pause/Step/Reset、慢动作与 RAF 清理
   - SVG/Canvas 剖面、曲轴端视图、气门升程图、压力曲线/P-V 图、参数控件、preset 保存与对比组件
5. 至少定义 EngineConfig、CrankState、PistonState、ValveState、StrokePhase、PressureSample、VolumeSample、CylinderState、SimulationTick、EnginePreset 等 TypeScript 类型。
6. 机械几何、相位判定、气门升程、容积与压力耦合、示功图、多缸相位、参数 clamp 与 tick 推进必须放在可测试的 simulation/domain 模块中。
7. 不允许使用 dangerouslySetInnerHTML，不允许把完整页面或大段组件写成字符串模板。

## 核心体验要求

1. 页面必须展示发动机剖面：气缸、活塞、连杆、曲轴、进气门、排气门与火花塞。
2. 提供 Play、Pause、Step、Reset 控制；Step 推进固定角度、不依赖动画帧率；支持慢动作。
3. 曲轴旋转时活塞上下运动，活塞位置必须来自 crank-slider 几何关系计算，不能手写固定 keyframes。
4. 清晰显示当前四冲程 phase（进气/压缩/做功/排气）、crank angle、RPM、piston displacement 与压力读数。
5. 做功阶段显示火花与压力上升。
6. 支持调节 RPM、曲柄半径、连杆长度、余隙（clearance）与点火提前角。
7. 支持保存一个参数 preset，并比较两个 preset 的最大压力、行程、压缩比、峰值时刻与指示功。
8. 360px viewport 下可操作关键控制并看到活塞剖面、气门升程、压力/示功图与当前状态。

## 重点难点要求

以下机制是机械教学模拟的高频失分点，请确保几何与数据自洽：

1. **压力与气缸容积耦合、示功图闭合**：气缸容积必须由活塞位置几何派生（余隙 + 缸径面积 × 位移）；压缩与做功阶段的压力必须与容积耦合（容积减小压力升高），而不是与几何脱钩的装饰性高斯。据此绘制 P-V 示功图，四冲程走完形成一条**闭合回路**，回路面积代表指示功。改变曲柄半径/连杆/余隙会改变压缩比，进而改变峰值压力与示功图形状。高频失败反例：压力是与容积无关的固定高斯、改参数压力不变、P-V 不闭合。
2. **气门升程曲线与配气正时（含气门重叠）**：进/排气门不是二元开/关，而是随曲轴角连续变化的升程曲线；配气正时要合理（进气门在进气冲程附近开启、排气门在排气冲程附近开启），并在上止点附近存在**进排气重叠（overlap）**。提供一张随曲轴角推进的气门升程图，剖面中气门开度随升程连续变化。高频失败反例：气门只有开/关两态、无升程曲线、无重叠。
3. **直列四缸相位与点火顺序**：模拟直列四缸，四个活塞由同一曲轴驱动、按 180° 相位偏移同步运动，点火顺序为 1-3-4-2；提供一个曲轴端视图显示四个曲拐的角度关系，四缸的冲程/点火时刻符合该顺序。剖面主视图可聚焦某一缸，但四缸相位必须同步一致。高频失败反例：多缸相位相同、点火顺序错误、端视图与主视图不一致。
4. **点火提前角影响峰值位置**：点火提前角必须影响做功阶段压力峰值出现的曲轴角位置，并在压力曲线/示功图上可见。
5. **确定性与联动**：相同参数与相同角度序列，活塞位置、容积、压力、气门升程、示功图必须完全一致（确定性）；压力曲线/示功图当前角标记、气门升程当前位置、剖面状态、曲轴端视图必须联动同一曲轴角。

## 模拟和稳定性要求

1. 参数变化不能产生 NaN、几何穿帮或负长度；连杆长度必须大于曲柄半径。
2. Stop/Reset 后曲轴、活塞、气门、压力/容积曲线与多缸相位状态必须一致。
3. 快速 Play/Pause/Reset 不得创建多个 RAF。
4. 参数非法输入要被 clamp 或拒绝，并给出可见反馈。
5. preset 对比必须来自真实 simulation 数据，不得写死。
6. reduced-motion 下仍可用 Step 模式观察完整四冲程与气门升程。
7. 控制台不能出现运行时报错、资源 404、React key 警告或未处理 Promise rejection。
