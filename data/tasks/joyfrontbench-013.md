二级分类：3D交互演示

请你扮演一名资深 CSS 3D 动效工程师与高级制表视觉设计师，设计并实现一枚原创的**立体镂空机械腕表**动态展示。

该页面用于高级制表概念展览。用户将本地双击打开成品，在无需联网、无需安装依赖的情况下观看腕表自动运转。完成结果必须让人第一眼识别为一枚**具有真实纵深、可从透视角度观察到多层机械结构上下叠放的、正在运行的高端立体镂空腕表**，而不是一张贴了阴影和渐变假装立体的平面表盘图，也不是普通网页时钟或电子仪表盘。

关键要求：这是一枚 **3D 立体**腕表，不是平面构图。观察者必须能看到表壳的厚度、机芯的纵深，以及齿轮、桥板、指针、表镜在不同高度上的层次关系。

最终只交付一个可直接运行的 `.html` 文件。

腕表品牌、Logo、表壳造型、机芯布局和装饰纹样必须原创，不得复制或明显模仿现实商业腕表及其商标元素。

## 一、交付与技术约束

整枚腕表必须使用 **CSS 3D 变换**构建立体结构：

* 至少一个建立透视的 `perspective` 容器（推荐 `800px`–`2000px`）；
* 主要层级使用 `transform-style: preserve-3d`，使子元素保留在同一 3D 空间中；
* 各主要部件通过 `translateZ` 分布在**不同深度**，并使用 `rotateX` / `rotateY` / `rotateZ` 表达方向与运动；
* 允许 `backface-visibility`、`perspective-origin`、`transform-origin` 等 3D 相关属性。

允许使用：

* 内联 CSS（含 3D transform、`@keyframes`、渐变、滤镜、阴影）；
* 内联 SVG 或普通 HTML 元素，**仅用于绘制单个部件的平面轮廓、齿形、纹理**；
* SMIL `<animate>` / `<animateTransform>`（若部件用 SVG 绘制）。

核心立体感必须来自 CSS 3D transform（真实的 `translateZ` 分层与 `rotate3d` / `rotateX/Y/Z`），**不得只给平面图叠加投影、渐变或高光来伪装立体**。

连续机械运动必须由 CSS animation（作用于 3D transform）或 SVG SMIL 驱动。允许少量内联 JavaScript 用于：可选的初始角度/展示视角控制，或在**页面加载时一次性程序化生成重复的静态 DOM**（如 60 个分钟刻度、齿轮及其轮齿、宝石/螺丝等）。但生成后不得再用 JavaScript、`requestAnimationFrame`、`setInterval`/`setTimeout` 逐帧改写这些元素来代替核心机械动画——所有连续运动仍必须由 CSS/SMIL 驱动。

关于交互式复杂功能（见第十节）的 JavaScript 边界：允许用 JavaScript 管理**离散状态**（走时/停走/设时切换、上链、动力储备数值、计时码表状态机）并据此设置指针/指示器；其中**计时码表**因需测量真实流逝时间，允许用 `requestAnimationFrame` 更新其计时指针。但这些都**不得接管或替代基础走时动画**——走时链齿轮、摆轮、擒纵、时针、分针与走时小秒针的连续运动必须始终由 CSS/SMIL 驱动。

禁止使用：

* **Canvas、WebGL、Three.js 或任何 3D 渲染库**；
* 外部图片、外部 SVG、base64 位图或 data URI 图片；
* 外部 CSS、JavaScript、字体、模型、视频、GIF、音频；
* CDN、iframe、网络 API 或任何运行时网络请求。

页面背景可以使用内联 CSS 绘制。保存后应能直接双击打开并自动播放。

## 二、立体视角与纵深构图

页面必须建立明确的透视，并让腕表处于一个**非正对屏幕的立体视角**，使厚度与纵深可见：

1. 使用 `perspective` 与 `perspective-origin` 建立透视投影；
2. 腕表整体绕 X 轴前倾约 15°–35°（可叠加轻微 Y 轴偏转），使观察者能看到表壳侧壁厚度与机芯高度差；
3. 必须满足以下之一，且都要让 3D 纵深清晰可辨：
   * **动态展示视角**：整表在小角度范围内持续缓慢往复倾斜或环绕（例如绕 Y 轴 ±10°–25° 往复），周期数秒以上、平滑无跳变；
   * **固定立体视角**：固定一个明显偏离正视的角度，静态即可看出多层纵深。

各部件沿 Z 轴的分层顺序（从底到顶）大致为：

```
机芯底板  →  齿轮系 / 摆轮 / 擒纵  →  桥板  →  刻度圈  →  时分秒针  →  表镜玻璃
```

相邻层之间必须有可观察的 `translateZ` 间距，形成真实的高度堆叠，而不是全部压在同一平面上。

页面还必须支持**人工拖拽浏览**：用户用鼠标或触摸拖动即可绕 X/Y 轴自由旋转整表，从任意角度观察机芯纵深；松手后视角保持，双击可复位。拖拽只改变展示视角（容器 3D transform），机械动画（齿轮、摆轮、擒纵、指针）在拖拽期间及之后必须持续运行、不被打断或代替。该视角控制属于允许的展示控制，可用少量 JavaScript 实现。

腕表不得在画面中悬空漂浮。必须提供一个**可见的展示承托结构**——斜靠式表架 / 表托 / 基座——让腕表倚靠或搁置其上并落于台面：

1. 承托结构与腕表处于同一 3D 空间、同一透视与光照，二者有明确的接触/支撑关系（例如表壳下缘落入托座、表背倚靠支柱），并在台面上投下接触阴影；
2. 承托结构在材质与造型上与腕表本体可区分（不是把机芯零件当作支架），且不遮挡机芯主要可视区域；
3. 人工拖拽旋转视角时，承托与腕表作为一个整体保持相对固定的支撑关系（一起旋转，如转台展示），不互相穿模或分离。

## 三、立体表壳与表镜

腕表外部必须包含：

1. 圆形或近圆形金属表壳，且**具有可见厚度**（顶圈、侧壁、底面通过 `translateZ` 与侧面元素表现）；
2. 至少两层可辨识的表圈，处于不同高度；
3. 与表壳自然连接的上、下表耳，具有立体厚度；
4. 右侧表冠，包含连接结构、圆柱主体和防滑纹理，作为从表壳侧壁凸出的立体部件；
5. 覆盖表盘、位于**最高 `translateZ`** 的透明表镜玻璃层，具有厚度或边缘高光，但不遮蔽机芯；
6. 表壳下方克制的环境投影，与立体视角一致。

表壳不能只是单色圆环，也不能是一张画了渐变的平面圆。必须通过多层圆环 + 侧壁 + `translateZ` 表现真实厚度与加工质感。

表镜只使用低透明度反射、边缘高光或轻微色偏，不得用大面积不透明填充盖住机械结构。

## 四、立体镂空机芯

中央区域必须保持明显的 Skeleton / Open-worked 结构，并具有**真实纵深**：透过镂空可以看到下方不同深度的机芯零件。不得使用完整实心表盘遮挡机芯，也不得把机械结构缩成中央的小型装饰。

机芯至少包含：

* 5 组主要传动齿轮；
* 1 组独立摆轮；
* 1 组可辨识的擒纵机构；
* 3 块可见桥板或支撑结构（位于齿轮之上、处于更高的 Z 层）；
* 5 个可辨识螺丝；
* 4 个位于齿轮轴心或桥板关键位置的宝石轴承；
* 若干轴、垫圈、固定环或微型连接结构。

### 立体传动齿轮

至少 5 组主要齿轮必须同时满足：

1. 每个齿轮是**有厚度的圆盘**（顶面 + 轮缘侧壁 / 齿），在立体视角下能看到盘面倾斜与侧面厚度，而不是零厚度的平面圆；
2. 包含大、中、小至少三种明显尺寸；
3. 具有可辨识的齿形、轮缘、辐条和中心轴；
4. 分布在机芯不同区域和**不同 Z 深度**，不全部重叠或集中于中心、也不全在同一高度；
5. 至少形成两组视觉上合理的相邻啮合关系；
6. 部分轴心通过桥板、宝石或螺丝形成结构联系。

**齿轮啮合的精确要求（严格）**——至少 3 组相邻齿轮必须构成真实啮合，而不仅是轮缘靠近或装饰性散布：

* **节圆相切**：啮合两轮中心距约等于两轮节圆半径之和；轮齿在啮合区交错咬合，齿顶伸入对方齿间，既不重叠穿模、也不留出明显缝隙或悬空；
* **模数一致**：相互啮合的齿轮使用一致的模数（即齿距与齿高相当），因此不同大小齿轮的单齿在物理尺寸上一致，能真正咬合；
* **转速与齿数成反比**：啮合齿轮的角速度与齿数成反比（齿数多者转得更慢），使啮合点线速度相等；相邻啮合的两轮**旋转方向必须相反**；
* 整个齿轮系至少体现 3 种不同的旋转周期，最小齿轮明显快于与其啮合的大齿轮。

每个齿轮围绕**自身轴心**旋转，旋转轴大致垂直于表盘平面（即绕表盘法线旋转）。可以复用基础齿轮定义，但不能让所有齿轮的尺寸、辐条、厚度和视觉处理完全相同。

### 立体摆轮

摆轮应位于机芯下半部或侧下方，是一个**有厚度的圆环**，清楚包含外圈、辐条、中心轴和支撑结构，可增加游丝或调速结构。

摆轮不是持续单向旋转的传动齿轮。它必须绕自身轴（表盘法线方向）在两个角度之间持续往复振荡，例如 `-18deg -> +18deg -> -18deg`，推荐振幅为单侧 12–24 度、周期 0.5–1.2 秒。不得做完整 360 度单向旋转。

### 立体擒纵机构

摆轮附近必须存在可辨识的擒纵轮与擒纵叉或锚形组件：

* 擒纵轮以离散小步或短暂停顿的方式前进；
* 擒纵叉在两个小角度之间周期摆动；
* 两者与摆轮使用相同或成整数比例的基础周期；
* 运动关系应表现为“摆轮往复、擒纵机构周期释放、齿轮系持续运行”，而不是静态装饰。

不要求钟表工程级物理仿真，但运动语义必须正确。

## 五、刻度与立体指针

表盘外圈必须包含：

* 12 个均匀分布的主时标；
* 正好 60 个分钟刻度位置；
* 其中每 5 分钟对应的 12 个刻度更长、更粗或更亮。

刻度应沿同心圆准确排列在刻度圈层，不与表壳、表冠或桥板严重冲突。刻度圈处于指针之下、机芯之上的 Z 层。

必须包含独立分组的时针、分针和秒针：

1. 三根指针共用同一中心轴，且分别位于**不同的 `translateZ` 高度**（例如时针最低、秒针最高），在立体视角下能看出针与针之间、针与表盘之间的高度差；
2. 时针最短且较宽，分针更长，秒针最细长；
3. 指针整体位于机芯和桥板之上、表镜高光之下；
4. 中心具有轴帽、轴承或其他固定结构，作为凸起的立体元件；
5. 三根指针分别绕表盘法线持续旋转，秒针最快、分针次之、时针最慢。

推荐使用接近真实钟表的完整周期：

* 秒针：约 60 秒一圈；
* 分针：约 3600 秒一圈；
* 时针：约 43200 秒一圈。

允许秒针连续扫描或机械式小步进，但三根指针不得同速、同相位或使用错误旋转中心。

## 六、机械动画规则

页面打开后所有机械动画自动播放，并无限循环。

主要齿轮必须全部旋转，并满足：

1. 至少一组相邻齿轮方向相反；
2. 至少使用 3 种不同旋转周期；
3. 小齿轮通常比相邻大齿轮更快，且啮合对满足齿数反比（节点线速度相等）；
4. 除擒纵轮的有意步进外，不出现周期结束时突然反向或跳回；
5. 所有齿轮始终围绕自己的真实轴心旋转，运行过程中啮合关系稳定，不出现互相穿模、错位或啮合处忽大忽小的缝隙。

摆轮、擒纵叉、擒纵轮、传动齿轮和三根指针必须同时存在可观察的实时运动。不得只让秒针或少数装饰部件运动。

动画运行至少 2 分钟后仍应保持：

* 旋转中心不偏移；
* 元素不逐渐漂移；
* 循环首尾无累积 transform；
* `preserve-3d` 层级不塌陷、Z 轴分层关系不改变；
* 若存在展示视角旋转，其往复/环绕平滑无跳变；
* 动画速度不会异常加快或减慢。

## 七、视觉风格

视觉定位为：

**现代高级制表 / 精密工业设计 / 镂空机芯艺术（立体展陈）**

推荐材料和颜色分工：

* 表壳与指针：冷银、钛灰或深钢色；
* 齿轮与局部桥板：暖金、黄铜或玫瑰金；
* 机芯底层：炭黑、深灰或低饱和蓝黑；
* 宝石轴承：红色、酒红或其他小面积高饱和色；
* 表镜：低透明度冷色反射。

立体感应主要由结构层次与光影共同表达：不同高度的部件在透视下自然产生遮挡与层叠关系，配合克制的阴影强化纵深。

深色背景不能牺牲可读性。表壳轮廓、齿形、桥板边缘、摆轮和指针在正常屏幕亮度下都应清楚可辨，不能大面积陷入纯黑。

使用多种渐变区分拉丝钢、抛光钢、暖金属、宝石和玻璃。阴影、模糊和光晕应克制，保持轮廓 sharp / precise / engineered。

避免：

* 卡通、玩具或图标化钟表；
* 霓虹赛博仪表盘；
* 大面积毛玻璃卡片或网页控制面板；
* 过度模糊、发光和纯黑遮蔽；
* 装饰性文字覆盖腕表主体；
* 齿轮、指针、刻度和桥板明显穿插或层级错误；
* **桥板或机芯底板大面积覆盖齿轮系，使多数齿轮无法辨认**——桥板应为纤细的支撑臂/条，齿轮系必须始终是最主要的可见内容；
* **只有平面图叠加阴影/渐变的假立体，缺少真实 `translateZ` 纵深**。

## 八、结构组织与复用

使用语义清晰的容器（`<div>` / `<g>` 等）组织至少以下结构，并明确各自的 3D 层级：

* 透视容器与整表 3D 舞台；
* 展示表架 / 基座 / 托座（承托腕表的结构）；
* 表壳、表耳、表冠（含厚度侧壁）；
* 机芯底层；
* 齿轮系及各主要齿轮；
* 桥板；
* 摆轮；
* 擒纵机构；
* 宝石与螺丝；
* 主时标与分钟刻度圈；
* 时针、分针、秒针；
* 表镜玻璃层。

具体 `id` / class 可以不同，但源码必须能够区分这些部件及其 `translateZ` 层级。不得把整枚腕表合并成一个不可理解的单一元素。

合理使用样式复用、`<use>`、CSS 变量或类，复用分钟刻度、齿轮齿、螺丝、宝石等重复结构。复用后仍需通过尺寸、位置、颜色、深度或局部细节形成变化。

若使用 SVG 绘制部件，根 SVG 或整表根容器应包含可访问的名称与描述（`<title>` / `<desc>` / `aria-label` 或等效方式）。

至少验证以下两个视口：

* 桌面：1440 x 900；
* 窄屏：390 x 844。

两个视口下均需满足：

4. 3D 结构不变形、不塌陷成平面；
5. 腕表占据主要视觉区域，同时保留可见边距；
6. 机芯细节不会因响应式处理被替换成简化占位图或退化为纯平面。

页面直接打开后控制台不得出现阻断性错误，不得发起运行时网络请求。

## 十、机械操作与复杂功能（进阶）

除观赏外，页面还需支持真实的机械操作与复杂功能。前提：**基础走时动画始终由 CSS/SMIL 驱动**（走时链齿轮、摆轮、擒纵、时/分针、走时小秒针）；下述交互只管理离散状态与派生计时（计时码表可用 `requestAnimationFrame` 更新其计时指针），不得借此接管基础走时动画。

### 上链、动力储备与走时状态机

1. **表冠可交互**：拖动表冠上链；双击（或等效操作）拉出/推回表冠以进入/退出「设时」。
2. **动力储备为派生指标**：随走时缓慢消耗、由上链回充，并有可见的动力储备指示（子盘指针或弧形量条），其数值随操作实时变化。
3. **走时状态机**：运行 / 停走 / 设时三态。动力储备耗尽为 0 时，走时链与时/分/秒针**停走**；上链使储备 > 0 后恢复走时。
4. **设时**：拉出表冠进入设时态，基础走时（含摆轮）暂停以便调整；拖动可拨动时针与分针；推回表冠后从新设定时间继续走时。

### 计时码表（Chronograph）

1. 至少两枚**推钮**：A = 启动/停止，B = 复位/分段（split）。
2. **状态机**：idle → running → stopped →（复位）idle；running 时按 B 进入/退出「分段保持」。
3. **中央计时秒针** + 至少一个累计子盘（如 30 分钟计），显示由计时**派生**的经过时间；可附 `mm:ss.cs` 数字读数。
4. **计时逻辑**：启动后计时秒针从当前累计位置连续前进；停止冻结读数并保留累计；**复位仅在停止/idle 时可用**，归零所有计时指针与读数；分段时显示保持而底层计时继续，取消分段后追上。
5. 计时码表与走时相互独立，且不得干扰或替代基础走时动画。

判分可通过操作后的可观察结果与 DOM/状态断言完成：上链改变储备、耗尽停走、设时拨针后继续走时、计时码表启停/复位/分段的正确迁移与派生读数。
