一级分类：网页 / 业务界面
二级分类：移动端应用界面

你是一名资深的移动端 App 设计与前端开发专家。请设计并实现一个**炫酷、现代、功能可用的移动端旅行预订 App**，并最终交付一个**完整、可直接运行的单 HTML 文件**（可保存为 `.html` 双击在浏览器打开，无需后端、无需联网、无需构建工具）。

页面按**移动端竖屏（约 390 × 844）**布局，建议在页面中央以一个手机外框（phone frame）承载整个 App。所有目的地、价格、预订等数据均使用内置的模拟数据（mock data），订单数据使用 `localStorage` 持久化，不接入任何真实后端。

### 一、视觉基调

1. 采用**深色 + 多彩背景 + 毛玻璃（frosted glass / glassmorphism）**风格：背景暗色且富有色彩层次，卡片与按钮为半透明磨砂质感（`backdrop-filter: blur`），边缘有细腻高光。
2. 整体要高端、精致、可直接上手使用，视觉风格统一，符合一线旅行类 App 的质感。
3. 不允许使用外部图片资源或 3D 模型文件。目的地缩略图、图标、装饰图形等**一律用纯 CSS / SVG / Canvas 代码绘制**（如用渐变色块 + 代码绘制的山/海/帐篷等意象表达不同类型的目的地）。

### 二、四个界面 + 底部导航

App 通过**底部标签栏（Tab Bar）**在以下四屏之间切换，切换时当前 Tab 高亮、内容区平滑过渡：

#### 屏 1 · 搜索 / 探索（Search）
- 顶部搜索框，可输入关键词过滤目的地（匹配名称或地点）。
- **多条件组合筛选**，各条件可同时叠加生效：
1. 类型筛选（酒店 / 岛屿 / 露营，可多选或单选切换）；
2. 价格区间（滑块或区间输入，按每晚价格过滤）；
3. 最低评分（如 ≥4.5 / ≥4.8）。
- **排序**：支持按价格（升/降）、按评分（降序）排序。
- 结果区展示**当前命中数量**；无结果时展示明确的空状态提示。
- 每个目的地卡片清晰展示 **名称、类型、地点、评分、每晚价格**，缩略图用代码绘制。
- 点击某个目的地卡片进入预订屏并**带入该目的地及其单价**。

#### 屏 2 · 日历预订（Book）
- 一个可交互的**月历**，可选择入住日期与退房日期（区间高亮）。日历必须遵守以下业务规则：
1. **不可选择今天之前的日期**（过去日期置灰不可点）；
2. 先点选入住日、再点选退房日；**退房必须晚于入住**，否则不接受该次点选或视为重新选择入住日；
3. **最短入住 1 晚**；
4. 支持**跨月选择**，切换月份后已选区间仍连续高亮；
5. 再次点击可**清空重选**；
6. **未选出完整合法区间时，「确认预订」按钮禁用**。
- 可选择入住人数 / 房间数。
- 根据「所选目的地单价 × 入住晚数 × 数量」**实时计算并展示总价**（晚数需按所选日期区间正确计算）。
- 「确认预订」后：生成订单并写入「我的行程」，展示预订成功反馈（目的地、日期区间、晚数、人数、总价等订单摘要）。

#### 屏 3 · 我的行程（Trips）
- 展示当前用户已生成的**订单列表**，每条订单展示目的地、日期区间、晚数、人数、总价、下单时间与状态。
- 订单数据使用 `localStorage` 持久化，**刷新页面后仍在**。
- 每条订单可**取消**：取消后该订单从"进行中"列表移除或标记为已取消，并有明确反馈。
- 订单为空时展示空状态提示与「去预订」引导。
- 底部 Tab 的「我的行程」上显示**进行中订单数量的角标**，随下单 / 取消实时更新。

#### 屏 4 · 我的 / 设置（Profile）
- 个人资料区（头像用代码绘制、用户名、简介等）。
- 一组**设置开关（Switch）**，如：推送通知、深色模式、位置服务、免打扰等，开关状态可切换并有明确视觉反馈。
- 可切换偏好项（如语言 / 货币），切换后相关展示（如价格货币符号）联动更新。

### 四、核心功能要求

1. **四屏结构与导航**：底部 Tab 切换四屏，切换有高亮与平滑过渡；「我的行程」Tab 有订单数量角标；各屏组件齐全。
2. **全代码绘制视觉与媒体展示**：缩略图、图标、头像等均用 CSS/SVG/Canvas 绘制，不引用外部图片；不同类型目的地视觉可区分、精致美观。
3. **多条件组合筛选与排序**：关键词 + 类型 + 价格区间 + 最低评分可同时叠加过滤，支持按价格/评分排序，命中数量正确，空态有提示。
4. **设置开关与偏好表单**：开关可切换且状态明确；偏好切换（语言/货币）后相关展示联动更新。
5. **日历业务规则**：过去日期不可选、退房晚于入住、最短 1 晚、跨月连续高亮、可重选、未选全则确认禁用。
6. **预订交易与算价**：按单价×晚数×数量正确实时算价；确认后生成订单并展示摘要。
7. **订单状态闭环与持久化**：下单写入「我的行程」并 localStorage 持久化（刷新保留）；可取消订单；角标随下单/取消实时更新；空态有引导。
8. **交互可用性**：各入口可点击、有状态反馈；跨屏带参（搜索→预订）正确；流程流畅。
9. **美观一致性**：毛玻璃暗色风格统一、精致；移动端竖屏下布局正确、无错位。

### 五、技术与交付约束

1. 交付**单个 HTML 文件**，HTML / CSS / JS 全部内联，可直接双击运行，不依赖任何外部资源、网络或构建工具。
2. 不接入真实后端；目的地/价格等用内置 mock 数据，订单用 `localStorage` 持久化。
3. 不允许出现引用未定义函数 / 未定义变量导致的运行报错；控制台不应有阻断功能的报错。
4. 所有状态变更必须正确驱动界面更新。
