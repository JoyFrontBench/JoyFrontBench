# 前端生成任务：积理 POS 业务配置中心——租户一键入驻

## 一、任务目标

请从 0 到 1 开发一个可以本地运行的企业级前端应用：“积理 POS 业务配置中心——租户一键入驻模块”。

本项目是纯前端项目，不连接真实后端、数据库或 POS 下游系统。所有租户信息、元数据、配置母版、业务实例、发布记录和接口请求均使用提供的模拟数据与前端模拟逻辑完成。

项目必须重点体现以下能力：

1. 企业级后台管理页面设计；
2. 多步骤向导流程；
3. 复杂动态表单；
4. 配置继承、覆盖和恢复继承；
5. 搜索、筛选、分页与状态展示；
6. 表单校验和跨字段业务规则；
7. 草稿保存与本地数据持久化；
8. 配置预览及 JSON 快照展示；
9. 模拟发布进度、失败和重试；
10. 完整的加载、空状态、错误状态和交互反馈。

## 二、技术要求

- 使用 React + TypeScript + Vite。
- 使用 React Router 管理页面路由。
- 可以使用 Ant Design、Arco Design 或其他成熟企业级组件库。
- 使用 Zustand、Redux Toolkit 或 React Context 管理跨页面状态。
- 使用 React Hook Form 配合 Zod，或其他等价方案完成表单校验。
- 使用提供的 JSON 文件作为初始数据。
- 使用 `localStorage` 持久化草稿、任务、实例和发布结果。
- 使用提供的 `mockApi.ts`，或自行实现等价的异步模拟接口层。
- 所有模拟接口必须具有加载延迟，不得在组件内部直接同步读取数据并立即展示。
- 项目必须能够通过 `npm install` 和 `npm run dev` 启动。
- 不需要实现真实后端服务。

## 四、核心业务规则

### 1. 配置三层模型

系统采用“元数据—母版—业务实例”三层模型。

- 元数据定义可以配置什么、字段类型、默认值、校验规则和配置分组。
- 母版定义某一业务场景下的一套标准配置值。
- 业务实例表示某一具体租户的实际配置。

最终有效值按以下优先级计算：

```text
租户覆盖值 > 母版值 > 元数据默认值
```

### 2. 三种配置来源

创建业务实例时支持：

1. 从母版创建；
2. 复制现有业务；
3. 新建空白配置。

从母版创建时，配置项默认继承母版值。

复制现有业务时，对源实例当前最终有效配置执行深拷贝。新实例后续修改不得影响源实例。

新建空白配置时，所有配置项默认使用元数据默认值。

### 3. 配置继承与覆盖

- 没有覆盖值时，配置项处于“继承中”状态。
- 用户修改配置后，配置项进入“已覆盖”状态。
- 已覆盖项需要高亮，并展示原始继承值、当前值和“恢复继承”按钮。
- 点击“恢复继承”后，删除该配置项的覆盖值，并恢复为母版值或元数据默认值。
- 右侧变更摘要需要实时展示覆盖项数量及明细。

### 4. 租户校验

输入租户 ID 后执行异步校验：

- 为空：提示“请输入租户 ID”；
- 不存在：提示“租户不存在”；
- 状态不是 ACTIVE：提示“当前租户状态不允许入驻”；
- 已存在于 `routeBindings.json`：提示“该租户已经完成入驻”；
- 存在未完成任务：展示“继续原任务”或“重新创建”；
- 校验成功：展示租户信息卡片。

### 5. 表单校验

至少实现：

- 必填项校验；
- 数值范围校验；
- 地址格式校验；
- 条件显隐字段校验；
- 路由 ID 唯一性校验；
- 业务身份编码格式校验；
- 大额退款审批阈值不得大于单笔最大退款金额；
- 默认支付方式必须是当前已启用的支付方式；
- 开启外卖后至少选择一个外卖平台；
- 启用小票 Logo 后必须填写 Logo 地址。

## 五、页面与路由

### 1. 入驻任务列表页 `/onboarding`

展示以下字段：

- 租户 ID；
- 租户名称；
- 业务场景；
- 配置来源；
- 当前状态；
- 当前步骤；
- 创建人；
- 创建时间；
- 最近修改时间；
- 操作。

支持：

- 按租户名称或租户 ID 搜索；
- 按状态筛选；
- 按业务场景筛选；
- 分页；
- 创建新入驻；
- 查看详情；
- 继续编辑；
- 重新发布。

状态至少包括：

- 草稿；
- 校验失败；
- 待发布；
- 发布中；
- 已发布；
- 发布失败。

### 2. 新建入驻向导 `/onboarding/new`

使用顶部步骤条，完整包含以下步骤：

#### 第一步：租户校验

- 输入租户 ID；
- 异步校验；
- 展示加载、成功、失败状态；
- 成功后展示租户信息。

#### 第二步：业务身份配置

字段包括：

- 路由 ID；
- 工厂 ID；
- 业务场景；
- 业务身份编码；
- 业务身份名称。

支持自动生成路由 ID 和业务身份编码。

#### 第三步：配置来源选择

使用卡片展示：

- 从母版创建；
- 复制现有业务；
- 新建空白配置。

选择母版时：

- 展示母版名称、场景、版本、状态、配置项数量和说明；
- 根据当前租户的门店类型，在匹配的可用母版上显示“推荐”标记；
- 停用母版不可选择；
- 支持按母版名称或关键词搜索母版，输入后更新母版列表；
- 支持按场景筛选。

复制现有业务时：

- 支持按租户名称、租户 ID 或实例编码搜索；
- 只允许复制已发布实例；
- 展示源实例的场景、版本、母版及最近发布时间。

#### 第四步：配置编辑

采用三栏布局：

- 左侧：配置分组导航；
- 中间：动态配置表单；
- 右侧：变更摘要。

需要根据 `metadata.json` 动态生成以下控件：

- 开关；
- 数字输入框；
- 文本输入框；
- 地址输入框；
- 单选下拉框；
- 多选框。

支持：

- 配置项搜索；
- 只看已覆盖项；
- 只看校验错误项；
- 条件显隐；
- 继承来源标签；
- 恢复继承；
- 修改前后值对比；
- 实时校验；
- 保存草稿。

#### 第五步：预校验与预览

展示：

- 租户信息；
- 业务身份；
- 配置来源；
- 配置项总数；
- 覆盖项数量；
- 校验结果；
- 错误和警告列表；
- 最终配置表格；
- 最终配置 JSON。

JSON 区域支持复制。

存在错误时禁止发布。

#### 第六步：模拟发布

按以下步骤展示进度：

1. 创建租户路由绑定；
2. 保存业务配置实例；
3. 生成最终配置快照；
4. 校验配置完整性；
5. 通知下游 POS 系统；
6. 完成发布。

每一步需要支持：

- 等待；
- 进行中；
- 成功；
- 失败。

发布按钮必须防止重复点击。

当 `mockConfig.json` 设置强制失败时，应在指定步骤失败，并展示失败原因和重新发布按钮。

#### 第七步：完成页

展示：

- 入驻成功或失败；
- 租户信息；
- 业务身份；
- 配置实例编码；
- 配置版本；
- 发布时间；
- 发布状态；
- 失败原因；
- 返回任务列表；
- 查看详情；
- 重新发布。

### 3. 任务详情页 `/onboarding/:id`

展示：

- 基本信息；
- 配置来源；
- 当前最终配置；
- 覆盖项明细；
- 发布记录；
- 操作日志；
- 历史版本入口。

## 六、模拟接口要求

至少封装以下异步函数：

- `validateTenant(tenantId)`
- `getMetadata()`
- `getTemplates(scenario?)`
- `getCopyableInstances(keyword?, scenario?)`

## 七、本地持久化要求

使用 `localStorage` 保存：

- 当前向导草稿；
- 新增入驻任务；
- 新增或修改的业务实例；
- 发布结果；
- 路由绑定；
- 发布记录。

页面刷新后：

- 未提交的向导数据可恢复；
- 已保存草稿不会丢失；
- 已发布结果仍可在任务列表中查看。

提供“重置模拟数据”功能，将本地数据恢复为初始 JSON 数据。

## 八、异常模拟面板

- 请求延迟；
- 租户查询失败；
- 母版加载失败；
- 草稿保存失败；
- 发布失败；
- 发布失败步骤；
- 重置模拟数据。

异常面板可以放在抽屉或弹窗中。

## 九、视觉与交互要求

- 采用企业级 SaaS 后台风格。
- 页面应具有统一的导航、标题、面包屑和内容区。
- 向导步骤清晰，当前步骤、已完成步骤和失败步骤有明显差异。
- 继承态使用弱化样式，覆盖态使用高亮样式。
- 所有按钮必须有真实交互，不允许只展示无响应按钮。
- 必须提供加载骨架、空状态、错误状态和成功反馈。
- 表单错误需要定位到具体配置项。
- 适配主流桌面宽度，在窄屏下不得出现严重遮挡。
- 不允许只实现静态页面或只完成首页。

## 十、代码质量要求

- 使用 TypeScript 定义租户、元数据、母版、实例、任务和发布记录类型。
- 页面、组件、服务、状态管理、工具函数分目录组织。
- 配置最终值计算封装为独立纯函数。
- 配置校验规则封装为独立模块。
- 避免在单个组件中堆积全部业务逻辑。
- 关键逻辑添加必要注释。
- 不允许使用大量 `any`。
- 控制台不得存在明显报错。
- 提供 README，说明启动方式、目录结构、模拟数据和核心业务规则。
